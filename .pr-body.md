## Summary

A connector connection's revoke is sticky against writes that started before it, and against an agent that starts its own authorization afterwards.

**Part 1 — the reported finding.** The guard enforcing the sticky revoke read the revoke time as `coalesce(metadata->>'revokedAt', '') < startedAt` in `apps/api/src/connectors/connection-status.ts`. Rows revoked by the 2026-09-17 migration carry `status = 'revoked'` and `updated_at` only, so they have no `revokedAt`; the coalesce yielded the empty string, `''` sorts before every ISO timestamp, and the guard passed. Any OAuth callback, device-flow poll or Composio finalize whose flow started before the revoke then wrote `revoked -> active` and stored its stale credential. The predicate now requires a real stamp that predates the flow; an unattributed revoke stays revoked.

**Part 2 — the review item (CWE-862).** The sibling `connect` transition left `revoked` unconditionally. `POST /projects/{projectId}/connectors/{slug}/connect` with `owner: "me"` is explicitly offered to agent sessions, and `ensureMemberConnection` (`apps/api/src/connectors/db-deps.ts`) matches a revoked row, so an agent session holding `project.connector.write` turned the account back to `active` and its finalize attached the agent's own authorization to it. `connectConnection` now takes a `ConnectAuthority` (`'person' | 'agent'`, default `'agent'`, fail-closed) and, for an agent, guards the UPDATE with `status <> 'revoked'` so a concurrent revoke still wins. Every call site states its authority:

| call site | authority | why |
|---|---|---|
| `connectors/computers.ts` `attachComputerConnection` | `person` | a person pairs a computer |
| `connectors/credentials.ts` `upsertConnectionCredential` with `connectNow` | `person` | reached only from `POST …/connections/{id}` `operation=credential`, behind `loadMutableConnection` |
| `projects/lib/connection-hosted-connect.ts` `startComposioConnect` | `agent` | reached from `POST …/connections/{id}` `operation=connect` (the agent's own "Connect" on its account) |
| `projects/routes/connection-actions.ts` activate | `person` | the route already refused an agent on a revoked row via `loadMutableConnection`; a person restores it |
| `connectors/db-deps.ts` `connectorConnect` (both writes) | `agent` (default) | `owner: "me"` is an agent session's own start; `owner: "project"` is the shared row a person shares |

The setup-link `/start` path reaches the same handler through `connectorConnect` and is therefore covered by the default.

Closes KRTX-4378
