# House rules (read by every agent)

This project is an **automated edutainment YouTube studio**: agents research, write, animate, voice,
package and publish science explainers at the Kurzgesagt / Veritasium / Fern quality bar. The loop
runs on Kortix; the deterministic parts run through the `yt` CLI (`bin/yt`).

## Map
| path | what |
|---|---|
| `agents/` | one agent per production role (showrunner is the default) |
| `skills/` | how-to for each stage + vendored HyperFrames skills |
| `rubrics/` | the quality bar per stage; the critic scores against these |
| `channel/` | channel bible (`brand.md`, `design.md`, `audio.md`) + `channel.yaml` config |
| `kit/` | house HyperFrames toolkit (`kit.css`, `kit.js`, templates) |
| `pipeline/` | the `yt` CLI source (TypeScript, bun) + tests + smoke fixture |
| `episodes/<slug>/` | one folder per video (layout below) |
| `memory/` | durable learnings (audience, hooks, visuals, packaging) |

## Episode layout
```
episode.yaml            state machine (stages, gates, costs, log) — change it only via bin/yt
01-brief.json           stage 1  topic & framing
02-research/            stage 2  dossier.md, claims.json, fact-check.json
03-script/              stage 3  script.json, script.md, timing.json (generated by `yt voice`)
04-visual/              stage 4  storyboard.json, styleframes/
05-scenes/<scene>.html  stage 5  HyperFrames compositions
06-sound/sound.json     stage 6  music cues (SFX live in the storyboard)
07-package/             stage 7  package.json, thumbnail.html
08-publish/             stage 8  description.txt, sources.md, publish.json, analytics/
qa/                     critic reviews, scene checks, contact sheets, gate packets
media/                  narration, music, SFX, thumbnail — NOT in git (object storage + media.lock.json)
```

## Non-negotiables
1. **Truth is traceable.** Facts enter only through `claims.json` and must be `verified` by the
   independent fact-checker before a script, scene or description may use them.
2. **Humans own the gates** (topic, script, storyboard, final). The narrator is cast per episode by the
   sound-editor within `channel.yaml → voice.casting` — no channel-wide voice, no voice gate. Agents never approve gates, never
   publish publicly without a human instruction (the CLI enforces the final gate).
3. **The maker never grades itself.** Stages with rubrics pass through the critic.
4. **State changes go through `bin/yt`.** Don't hand-edit `episode.yaml`, `timing.json`, or the
   `@cues` blocks in scenes.
5. **No heavy media in git.** Audio/video/renders live in `media/` and `build/` (git-ignored) and are
   mirrored with `bin/yt media push`.
6. **No fabricated people, quotes, studies or footage; no AI likeness of real people;** generative
   b-roll only for atmosphere and only when `channel.yaml` enables it.
7. **Originality per episode.** Reuse components, not compositions; YouTube demonetises templated
   mass production channel-wide.

## Commands you'll use
`bin/yt help` lists everything. Essentials: `episode next|start|complete`, `validate`, `claims apply`,
`script lint|md`, `voice`, `scene scaffold|check|retime`, `sound`, `render`, `qa final`, `thumb`,
`sources`, `gate request|sync`, `youtube upload|schedule|analytics`, `smoke`.

## Environment
Sessions run on **pi**. The project is `kortix_version: 3`: each agent is one block in `kortix.yaml`
(behaviour and grants) whose `prompt_file` is `agents/<name>.md`, and skills are registered under
`skills:` and enabled per agent by name.
- Skills are files: read `skills/<name>/SKILL.md` (your system prompt lists the ones you may use).
- The web is reached with `web_search` and `scrape_webpage`; there is no `webfetch`, todo or skill tool.
- Subagents (`task`) can't start further subagents or ask the user questions — report questions back.
- Models: agents carry no per-agent pin; they all run on the project's default model
  (`kortix models default`), so one setting moves the whole agency.

Sandboxes use the `video` template (`Dockerfile.video`, 6 vCPU): Node 22, HyperFrames 0.8.151 +
Chrome, ffmpeg, bun. Rendering is CPU-only (measured ~2.6× realtime on 4 vCPU). `YT_OFFLINE=1` stubs
all paid audio APIs for dry runs. Use `pnpm`/`bun` for JS; `uv run --with <pkg>` for one-off Python.
