# Kortix Mobile — design approach

Read this before building or restyling any screen in `apps/mobile`. It records
the patterns Jay has signed off on, with the exact values. `CLAUDE.md` in this
folder holds the primitive rules (which component to use); this file holds the
layout and visual decisions (how a screen looks).

When a rule here conflicts with an older screen, the rule wins. Convert the
screen when you touch it.

## 1. Settings screens

Every settings-style screen uses one layout, built from
`@/components/kortix/settings-list`: the Account page, the `(settings)`
sub-pages (Sounds, Notifications, Language, Delete account), Accounts,
Billing, and Plans. Do not hand-roll headers, rows, dividers, or group titles.

There is **one settings page**: the Account page
(`components/settings/AccountPage.tsx`). The project sidebar's avatar opens
it inside the project stack at `/projects/[id]/account` — its only entry
point since the tab bar was removed (COR-161). There is no `(settings)` index screen and no General
page.

| Export | Use |
| --- | --- |
| `SettingsHeader` | Back button + title + optional trailing action. `(settings)` screens get it from `_layout.tsx`; root-stack screens (`/accounts/[id]`, `/billing`) render it themselves with `Stack.Screen options={{ headerShown: false }}`; project pages (Sessions, Account) pass `onOpenMenu`, which replaces Go back with the hamburger (`MenuButton`); `largeTitle` moves the title below the control row as an `h3` (Sessions) |
| `SettingsPage` | Scroll body. Default bottom padding: safe-area inset + 28pt |
| `SettingsGroup` | Titled, borderless rounded card with full-width separators |
| `SettingsRow` | icon (or `leading`) · label · trailing |
| `AppearanceRow` | The Appearance row: current mode as its value; opens a dialog with System, Light, Dark (icon · label · check) |

```tsx
import { SettingsGroup, SettingsPage, SettingsRow } from '@/components/kortix/settings-list';

<SettingsPage>
  <SettingsGroup title="Preferences">
    <AppearanceRow />
    <SettingsRow icon={Volume2} label="Sounds" onPress={() => go('/(settings)/sounds')} />
  </SettingsGroup>
  <SettingsGroup title="Help">
    <SettingsRow icon={BookOpen} label="Docs" external onPress={openDocs} />
  </SettingsGroup>
</SettingsPage>
```

### Page

| Property | Value |
| --- | --- |
| Body | `SettingsPage` — `ScrollView`, `bg-background`, no scroll indicator |
| Side margin | `px-4` (16pt) — `SettingsPage`'s default `gutter="project"`. **One edge for every settings-style screen** (Jay, 2026-09-22): the project's Account page, Sounds, Notifications, Language, Billing, Plans and `/accounts/[id]`. A 20pt `gutter="page"` is available but nothing uses it |
| Space between groups | 18pt |
| Bottom padding | safe-area inset + 28pt |
| Content above groups | `header` prop (e.g. the profile photo on the Account page) |
| Pinned bottom action | render the pill below `SettingsPage` in a `bg-background px-5 pt-3` view with `max(insets.bottom, 16)` bottom padding, and pass `paddingBottom={24}` to the page (Plans) |
| Full-bleed hero | `hero` prop (no screen uses it since Billing dropped its hero, 2026-09-24). The hero scrolls with the page; the body sits on a `rounded-t-3xl bg-background` sheet that overlaps the hero’s bottom 24pt, so the hero keeps ≥ 24pt bottom padding |

### Header

| Property | Value |
| --- | --- |
| Component | `SettingsHeader` from `settings-list` — one header for every settings-style screen |
| Go back | `PlatformButton` — native SwiftUI button on iOS (`chevron.left`, plain style on the `secondary` fill), `Button variant="secondary"` icon pill on Android |
| Back behaviour | `router.back()`; if there is no history, `router.replace('/projects')` |
| Title | screen name, sentence case |
| Trailing action | `right` prop — e.g. `PlatformButton label="New" systemImage="plus"` for a create action |
| Hero header | `align="center"` + `transparent` over a `SettingsPage` hero. Pair a centred title with icon-only actions; an empty side gets a 40pt spacer |

Register a new `(settings)` screen in `_layout.tsx` with
`header: () => <SettingsHeader title="…" />`.

### Group

| Property | Value |
| --- | --- |
| Title | `Text variant="muted"`, `mb-2 px-4`, **sentence case** ("Sound pack", not "SOUND PACK"). Never uppercase, never letter-spaced eyebrows |
| Surface | **Each row is its own tile** (Jay, 2026-09-22): `bg-card`, **no border**, `overflow-hidden` (it clips the row's pressed fill). The group's outer corners are `rounded-2xl` (16pt: first row top, last row bottom); the corners between two rows are `rounded-md`. A one-row group is one fully `rounded-2xl` tile. `SettingsGroup`'s `className` overrides the tile surface (`bg-secondary` inside a sheet) |
| Dividers | No hairline. A 2pt gap between tiles (`ROW_GAP` in `settings-list.tsx`), set by `SettingsGroup`: what is behind the group shows through it — `bg-background` on a page, the sheet colour in a sheet. Rows never draw their own divider |
| Empty group | renders nothing — conditional rows (`{cond && <SettingsRow/>}`) are safe |

### Row

A row is **icon · label · trailing**. Nothing else.

| Property | Value |
| --- | --- |
| Padding | `px-4 py-3` (py one step below px — see §2 Spacing) |
| Icon | Phosphor from `@/lib/icons` at the app weight (no `weight` prop), `size={18}`, `text-foreground/80`, centred in a leading slot at least 20pt wide (`min-w-5`) so every label aligns. A row with no `icon` and no `leading` drops the slot and its `mr-3` gap, so its label starts at the card padding. A loading row keeps the slot with a `<Skeleton>` so its label does not shift |
| Custom leading | `leading` prop instead of `icon` — flag emoji (`Text variant="large"`) on Language, `Avatar variant="custom" size={28}` on the new project sheet's Account picker |
| Label | `Text` default variant, one line, sentence case ("Edit profile", "Delete account") |
| Long label | `multiline` prop wraps the label instead of truncating it. Only for list content that is the label itself: plan features on Plans and the upgrade sheet (`Check` icon · feature). Never a way to add a description |
| Description | **none**. Do not add a second line under the label. One exception: the Account page's **profile tile** (name over email, below), the only two-line row in the app (Jay, 2026-09-23) |
| Chevron (navigates in-app) | `CaretRightIcon`, `size={16}`, `text-muted-foreground/70` — shown automatically when the row has `onPress` |
| External link (opens browser) | `external` prop → `ArrowUpRightIcon`, same size |
| Read-only value | `value` prop → muted text on the right, max 60% width, one line (e.g. the account email) |
| Inline control | `right` prop → `Switch`, `ToggleGroup`, check mark, icon button. Replaces the chevron |
| Selected option (picker) | `checked` prop → primary check mark. Picker rows also pass `right={null}` so no chevron shows (Sound pack, Language, the new project sheet's Account picker) |
| Appearance | always `<AppearanceRow />` — a `Dialog` (not a page, not an inline toggle) listing System, Light, Dark in that order, each with its icon (`Monitor`, `Sun`, `Moon`) and a check on the active mode, in a `SettingsGroup` on the `bg-popover` dialog; choosing applies and closes. Dialog width is explicit — `min(window width − 32, 420)` — because `w-full` collapses to content inside the native overlay wrappers |
| Destructive | `destructive` prop → icon and label `text-destructive`. Log out is now a neutral row (not `destructive`); Delete account is a quiet text link below the version footer, not a `SettingsRow` |
| Badge | `badge` prop → small destructive pill after the label (e.g. "Scheduled") |
| Plan badge | `PricingTierBadge` in `right` (Account page email row). Legacy tiers (Basic, Plus, Pro, Ultra) render their SVG artwork. Any other plan name renders a pill in the artwork's shape: full radius, `THEME.light.border` fill and `THEME.light.foreground` text in both themes, label at 55% of the pill height. Never leave the slot empty |
| Press feedback | background highlight `active:bg-accent`. Never scale a row inside a card |

A destructive action confirms in an `AlertDialog` that opens after the sheet has closed — never two overlays at once |

Its `pageId` param never changes, so the screen under it keeps its content and state (scroll, open rows). The drawer opens from every project route (hamburger or left-edge swipe). Drawer moves (`drawerRouteMove`, `returnHomeMove`): Search (→ `sessions`, `autoFocusSearch`) / Files / avatar push over home, replace a covering route, and do nothing when that route is already on top; under sub-pages they pop back to that route when it is the one under them (`pop-to`), else reset to `[index, route]` (`reset`, `homeAndRoute` keeps home mounted) — so a drawer move never leaves the stack deeper than one screen over home; Review goes through the tab store's `navigateToPage('page:review')` instead of a drawer route, so the same push/replace happens through `ProjectHomeRoute`/`useCoveringRoute`, not `drawerRouteMove`; a session row only updates the tab store (home pushes `view`, an open `view` swaps its content, a covering route replaces itself with `view` — `useCoveringRoute`); New session resets the store and pops to home (`StackActions.popTo('index')`); the switcher row's picked project (COR-124/COR-157 Task 4) `router.replace`s to it directly, closing the drawer with the switcher sheet — the old "All projects" row and the tappable-nothing logomark are gone (**Project sidebar**, §6). Never replace `view` with `view`: the old view's cleanup would close the session that just opened. Back: Android back closes an open drawer, else pops a sub-page one level (`androidBackMove` → `pop`, `backFromSubPage`; with nothing under it — a deep link — it replaces it with home), else pops a covering route to project home, else on home is left to the system. iOS has no swipe-back in the project stack (`gestureEnabled: false`, `fullScreenGestureEnabled: false`): the left edge opens the drawer on every project route — except a sub-page (`projectEdgeGesture` → `back`): its screen sets `gestureEnabled: true` and the drawer's `swipeEnabled` is off while it is on top, so there the left edge is the iOS swipe-back. One edge gesture, one meaning per screen. A sub-page leaves when the store leaves the home state while it is focused (`subPageLeaveMove`): a view under it is popped to and swaps its content; otherwise the stack resets to `[index, view]`. Sub-pages are pushed only from screens that show while the store is home (Settings, project Settings), and removing one never resets the store. `projects/[id]` itself has `gestureEnabled: false` and always opens with `router.replace`, so no screen sits under a project. The Projects list (`/projects`) is not reached from a project; the switcher sheet replaces it. A project always opens on project home: the tab store neither restores nor persists the active page or thread |
| App start | `app/index.tsx` is the door (web `/projects/start`): signed out → `/auth`; signed in → the last project this user opened (`useLastProjectStore`, keyed by user id), else the first project (`lib/projects/landing.ts`: selected account, then owned/admin, then member accounts), via `router.replace`. With no project in any account: the upgrade screen once per user (`/welcome`), then `/new` — never the empty list (§4 **First run**, `startDestination` in `lib/onboarding/onboarding.ts`). Failure: 2 retries, then a centred message (`large` title, `muted` line) chosen by `lib/projects/start-failure.ts`: unreachable → "Can't reach Kortix" / server error → "Could not open your project", each with `size="lg"` pills Try again (primary) · All projects (secondary, opens `/projects`) · Sign out (ghost); a 401/403 → "Your session has ended" with one primary pill Sign in again. Never a dead end, never an automatic fall back to the list. Every implicit redirect (sign-in, back with no history, leaving an account) goes to `/`, never `/projects` |
| Push transition | Every stack (root, `(settings)`, `auth`, project) is expo-router's native `Stack` with the platform default push/pop on iOS and Android — no custom animation. The root `index` redirect has `animation: 'none'`. Swipe-back is iOS-only, and off in the project stack (its left edge opens the drawer) except on a sub-page (`page`), where it is on and the drawer swipe is off; Android uses the system back gesture. |
| Confirmations | `AlertDialog` (`rounded-3xl` content — `Dialog` and `AlertDialog` are borderless in the primitives, on `bg-popover` — the same surface as bottom sheets — over a `bg-black/70` overlay; call sites never set a background; footer: destructive `Button size="lg" rounded-full` + `AlertDialogCancel asChild` secondary pill). Never `Alert.alert`. Sign out, Delete account, and Keep current plan keep the dialog open while they run and show a failure in the description. Delete account always asks for a typed confirm word and then a second question with a delayed Delete button (both timings); taps alone never delete. Keep current plan confirms with the buttons alone, and a safe action (Cancel deletion) does not confirm. A plain confirm (title · description · Cancel · action) is `useConfirmDialog()` (`components/kortix/confirm-dialog.tsx`, COR-151): `confirm({ title, description, confirmLabel, destructive, onConfirm })` + render its `dialog` once; it portals into `OVERLAY_PORTAL_HOST`, above an open sheet. Merge always confirms (Review is the only Merge surface). `Alert.alert` is allowed only for a one-button acknowledgement the toast cannot carry (a native `Modal` covers the toaster on Android — `FileViewer`'s Save failed) |
| Results | Success of an action that leaves the page in place → `useToast().success`; a failure outside a dialog → `useToast().error`. Never `Alert.alert`. Values: §11 Toasts |
| External links | `openLink(url)` (`lib/utils/open-link.ts`, COR-151) is the one way to open a web link. `linkTarget` (`lib/utils/link-target.ts`, bun-tested) decides: `kortix.com` and every subdomain (docs, support, pages, staging) → the in-app browser (`WebBrowser.openBrowserAsync`); any other host (GitHub, a markdown link) → the system browser (`Linking.openURL`). Not for OAuth / checkout / connector round trips that wait for a `kortix://` redirect (`openAuthSessionAsync`), `tel:` / `mailto:`, or the Browser page's explicit "Open in browser" |

### Copy

- Labels name the destination or setting in 1–2 words, sentence case.
- Group titles group by user intent: Preferences, Profile, Account, Help,
  Sound pack, Sound events, Feedback. The Advanced group is gone (COR-122,
  COR-126) — nothing groups under that title any more.
- A destructive action lives in its own group, at the bottom of the screen
  it belongs to (e.g. Delete project on the project Settings page).

## 2. Spacing

Padding is written as plain Tailwind classes in each component — no shared spacing module. Mobile uses stock Tailwind spacing (1 unit = 4pt: `px-4` = 16pt). The values below are the only ones to use.

Jay's rule (2026-09-16): **vertical padding is one Tailwind step below horizontal padding** on every padded row, list item, and inset block. Pick the side padding for the surface, then take one step off for the top and bottom.

| Pair | Pt | Use |
| --- | --- | --- |
| `px-3 py-2` | 12 / 8 | Edge rows: project sidebar session rows and Previous chats, inside an `mx-4` column so the highlight box starts on the 16pt edge and the content on the 28pt edge |
| `px-4 py-3` | 16 / 12 | Rows inside a card or group (`SettingsRow`, Sessions page rows) — the default |
| `px-5 py-4` | 20 / 16 | Roomy blocks and page sections |

- Never set py below px − 1 step (`px-4 py-1.5` reads cramped) or equal to px (`px-4 py-4` reads loose).
- Side edges: 16pt (`px-4`) everywhere — project pages (Jay, 2026-09-16 — 12pt was too tight) AND every settings-style screen, which used to sit at 20pt and read as a different app beside the project's Account page (Jay, 2026-09-22).
- A control's icon sits on the padding edge, not the control's box: `MenuButton` pulls itself left by `-ml-2.5` so the hamburger glyph lines up with the title and list below it.
- Fixed-height controls (`Button` sizes, 40/44pt inputs) keep their size variants; this rule is for padded content, not for `Button` boxes.

| Situation | Use |

## 11. Toasts

`useToast()` (`components/kortix/toast-provider.tsx`) is the only toast. **`sonner-native` renders them** (https://sonner-native.netlify.app; Jay, 2026-09-22): the library owns the stack, the swipe, the timers, the layout and the motion, so the app does not reimplement any of it. Web's toast (`apps/web/src/components/ui/toast.tsx`, Sonner) stays the behaviour spec. The app owns three things only: the API seam (`toast-provider.tsx`), the look (`toast.tsx`), and the rules in `lib/ui/toast-model.ts` (durations, haptics, message helpers — pure and tested). No screen imports `sonner-native` directly.

| Property | Value |
| --- | --- |
| API | `toast.success / error / info / warning / loading(message, { description?, duration?, id?, action? })` → the toast's id. `toast.promise(promiseOrFn, { loading, success, error? })` — a loading toast that turns into the success or error toast **in place**, returns the promise; no `error` = no error toast (web's `loadingToast`). `toast.dismiss(id?)` — one, or all |
| When | Success of an action that leaves the page in place → `success`; a failure outside a dialog → `error`. Never `Alert.alert`. A failure inside a dialog stays in the dialog |
| Position | `position="top-center"`, `gap={8}` between toasts, `offset={insets.top + 8}` — the library measures `offset` from the SCREEN edge, not the safe area, so the inset is added here or the toast sits under the status bar / notch (Jay, 2026-09-22) |
| Card | The app's floating-surface rule, `FloatingTabCapsule`'s (§6; Jay, 2026-09-22 — the bordered light card was rejected): light `background` lifted by `LIGHT_SHADOW` (`0px 6px 24px` foreground at 0.12, the one token in `FloatingTabBar`), **no border**; dark `card` + hairline `border`, no shadow (a shadow is invisible on black). | Icon | 20pt, **one family: every type is `weight="fill"`** (Jay, 2026-09-22 — mixed fill and outline read as two icon sets), in its brand tone: success `CheckCircleIcon` green · error `XCircleIcon` red · info `InfoIcon` blue (not the warning circle web uses — it read as a warning) · warning `WarningIcon` yellow · loading `KortixLoader size="small"` (never a spun icon), passed through `<Toaster icons={…}>` |

| Close | **Only on a toast that never leaves on its own** — loading, or `duration: Infinity` (`toastKeepsCloseButton`, tested; Jay, 2026-09-22).
