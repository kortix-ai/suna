A volume is storage you already own, mounted into an agent's sessions as an
ordinary directory at `/volumes/<name>`. The agent uses it with the tools it
already has: `ls`, `cat`, `grep`, its edit tool, and scripts. It needs no
new tool and no instructions from you.

Kortix does not host the storage. A volume is a pointer to your bucket plus
the identifiers of the [project secrets](/docs/project/secrets) that hold its
credentials. `kortix.yaml` never contains a credential value.

Use a volume when the agent needs data that does not belong in the
repository, or must write output somewhere durable outside it:

- datasets, media, and document archives larger than a Git repository should hold
- reports and exports another system picks up from a bucket
- files shared between agents, triggers, and your own services

## Supported storage

`type: s3` covers Amazon S3 and every S3-compatible service: Cloudflare R2,
Google Cloud Storage (XML interoperability API), MinIO, Tigris, Wasabi,
Backblaze B2, and DigitalOcean Spaces. Set `endpoint` for any service other
than Amazon S3.

## Declare and attach

Declare volumes at the top level. Attach them to agents in `agents:`.

```yaml
volumes:
  datasets:
    type: s3
    bucket: acme-data
    prefix: training/2026
    access_key_id: DATASETS_KEY_ID
    secret_access_key: DATASETS_SECRET
  reports:
    type: s3
    bucket: acme-reports
    endpoint: https://<account-id>.r2.cloudflarestorage.com
    access_key_id: R2_KEY_ID
    secret_access_key: R2_SECRET
  noaa:
    type: s3
    bucket: noaa-ghcn-pds          # a public bucket: no credentials

agents:
  analyst:
    secrets: [DATASETS_KEY_ID, DATASETS_SECRET, R2_KEY_ID, R2_SECRET]
    volumes:
      datasets: read-only
      reports: read-write
      noaa: read-only
```

1. Store the credentials as project secrets: `kortix secrets set
   DATASETS_KEY_ID=<value>`, or the project's Secrets page. A new secret has
   **Environment** exposure, which a volume needs.
2. Declare the volume. `access_key_id` and `secret_access_key` name the
   secret identifiers. Omit both for a public bucket.
3. Attach the volume to each agent that needs it. A list attaches every
   volume read-only (`volumes: [datasets, noaa]`); a map sets the mode per
   volume.
4. Grant the same agent every credential secret of every volume it attaches,
   in `secrets:`. `kortix validate` rejects the manifest otherwise.
5. Merge the change to `main`. Sessions created after the merge mount the
   volumes.

The full field list is in the [manifest reference](/docs/project/manifest#volumes).

## What the agent sees

When a session starts, the sandbox mounts every attached volume before the
agent's first turn. It waits at most 10 seconds, in parallel with the
repository checkout, so a session without volumes pays nothing. The agent's
context lists each volume with its source, mode, and state:

```text
## Volumes

External storage is mounted as ordinary directories under /volumes. Use your normal file tools on them (ls, cat, grep, edit).

- `/volumes/datasets`: s3://acme-data/training/2026 (read-only).
- `/volumes/reports`: s3://acme-reports at https://<account-id>.r2.cloudflarestorage.com (read-write).
- `/volumes/noaa`: s3://noaa-ghcn-pds (read-only).
```

A volume that cannot mount is listed with its reason, for example
`` `/volumes/reports`: NOT MOUNTED. credential secret "R2_SECRET" is not delivered to this session: … ``.
It never blocks the session. The agent keeps working with every volume that
did mount.

## Credentials and security

:::warning[Attaching a volume gives the agent its credentials]
The mount runs inside the agent's own sandbox, where the agent has root
access. An agent that attaches a volume can read that volume's key. This is
why the credentials must be in the agent's `secrets:` grant: the grant states
the access out loud. Use a key scoped to the one bucket or prefix, with
read-only permissions for a `read-only` volume.
:::

- Credential secrets need **Environment** exposure. An egress-enforced or
  `none` secret never reaches the sandbox, so it cannot sign S3 requests, and
  the volume reports NOT MOUNTED with that reason.
- The credentials reach the mount process through its environment, never its
  command line.
- `read-write` lets the agent delete objects. Turn on bucket versioning for
  data you cannot recreate.

## Object storage, not a disk

A mounted bucket behaves like a directory for reading, writing, and editing
files. The storage underneath still has limits:

| Behavior | What happens |
|---|---|
| A write | reaches the bucket about 5 seconds after the file is closed |
| An append (`>>`) | re-uploads the whole object |
| A rename or move | copies the object, then deletes the old one |
| Symlinks | not supported (`I/O error`) |
| Empty directories | not kept; a directory exists while it holds a file |
| Changes made outside the session | appear within 1 minute |
| Two sessions write one file | the last write wins; there is no locking |
| The storage is unreachable | every operation on the volume returns `I/O error` |

Reads are cached on the sandbox disk (up to 2 GB per volume), so a second
`grep` over the same file does not download it again. A recursive search of a
bucket with millions of objects lists and downloads every object; point the
agent at a narrow prefix instead.

A write that has not reached the bucket yet survives a sandbox restart: the
cache lives on the sandbox's persistent disk, and the next mount uploads it.

## Troubleshooting

Each volume writes its log to `/var/log/kortix-volumes/<name>.log` in the
sandbox.

| NOT MOUNTED reason | Fix |
|---|---|
| `credential secret "X" is not delivered to this session` | Create secret `X` in the project and add it to the agent's `secrets:` grant. |
| `credential secret "X" uses … delivery` | Set the secret's exposure to **Environment**. |
| `… AccessDenied …` / `… NoSuchBucket …` | Check the key's permissions, the bucket name, and `endpoint`. |
| `rclone is not installed in this sandbox image` | The project's sandbox image predates volumes. Rebuild the sandbox template. |
| `rclone did not mount within 60 s` | Check that the endpoint is reachable from the internet. |

## Limits

- `type: s3` is the only type. Other storage protocols are not supported.
- A volume mounts in project sessions. The experimental split pi worker
  (`pi_worker` flag) mounts no volumes, as it receives no project secrets.
- A secret rotated while a session runs applies to the next session.
