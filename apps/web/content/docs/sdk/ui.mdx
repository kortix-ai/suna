`@kortix/ui` is the React component library that the Kortix web app renders. The same package serves Kortix Apps, white-label hosts and your own app, so a button, a modal or a chat thread looks and behaves the same everywhere. Components are Tailwind CSS v4 class strings that read CSS variables. You re-theme them with a typed theme (`@kortix/ui/theme`) or by overriding the variables, never by copying a component.

<Callout type="warning">
`@kortix/ui` is not on npm yet. Today it is a workspace package of the [kortix-ai/suna](https://github.com/kortix-ai/suna) repository: inside that repository, add `"@kortix/ui": "workspace:*"` to your package's dependencies. This page describes the package as it ships there.
</Callout>

## Add the styles

Load the styles once, in your app's main stylesheet or entry file. Pick the row for your host.

<Tabs>
<Tab title="Tailwind CSS v4 host">
Import `@kortix/ui/tailwind.css` after Tailwind. It brings the tokens (`tokens.css`), the component layer (`theme.css`: the `dark` variant, the `@theme` keys the component classes resolve against, the utilities and the keyframes), the animation utilities and the scrollbar plugins. `theme.css` also adds an `@source` rule, so Tailwind scans the package for class names.

```css title="app.css"
@import 'tailwindcss';
@import '@kortix/ui/tailwind.css';
```

Your own classes resolve against the same tokens: `bg-background`, `text-muted-foreground`, `border-border`.

<Callout type="warning">
`tokens.css` sets `--spacing: 0.23rem`, 8% tighter than Tailwind's `0.25rem`. Your own spacing utilities follow it: `p-4` is 14.72px, not 16px. To keep stock Tailwind spacing for your own classes, set `--spacing: 0.25rem` in `:root` after the import. The components then render 8% larger.
</Callout>

To bring your own token values instead of `tokens.css`, import the parts one by one. Every line except `tokens.css` is required: without `tw-animate-css` and the two plugins, overlays lose their enter and exit animations and `scrollbar-hide` does nothing, and the build reports no error.

```css title="app.css"
@import 'tailwindcss';
@import 'tw-animate-css';
@import '@kortix/ui/tokens.css'; /* optional: or set every variable yourself */
@import '@kortix/ui/theme.css';
@plugin 'tailwind-scrollbar';
@plugin 'tailwind-scrollbar-hide';
```
</Tab>
<Tab title="Host without Tailwind">
Import one prebuilt file. It holds the reset, the tokens and every class the components use.

```ts title="main.tsx"
import '@kortix/ui/styles.css';
```

It holds no class that only your own code uses. Style your own markup with plain CSS that reads the variables, such as `var(--border)`.
</Tab>
</Tabs>

- Dark mode is the `dark` class on `<html>`. Add or remove it to switch themes. `useIsDark()` returns the current state.
- Both paths style the page itself: `body` paints `--background` and `--foreground`, borders default to `--border`, native controls follow the theme (`color-scheme`), text selection reads `--selection`, and interactive elements show the pointer cursor. You add no base rules of your own.
- `@kortix/ui/fonts.css` loads the Roobert font, for Kortix-owned surfaces only. Every other host renders the system font stack (`--font-sans-system`).

## Mount the providers

Mount these once, at the root of your app:

```tsx title="providers.tsx"
import { UiProvider, type UiLinkComponent } from '@kortix/ui';
import { IconProvider } from '@kortix/ui/icon-provider';
import { Toaster } from '@kortix/ui/toast';
import { Link } from 'react-router-dom';

// Any router: `UiProvider` passes anchor props with `href` and a Next.js-style `prefetch` hint.
const RouterLink: UiLinkComponent = ({ href, prefetch: _prefetch, ...props }) => <Link to={href} {...props} />;

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <UiProvider strings={{ confirm: 'Confirm', cancel: 'Cancel' }} link={RouterLink}>
      <IconProvider>
        {children}
        <Toaster />
      </IconProvider>
    </UiProvider>
  );
}
```

| Provider | What it does | Without it |
| --- | --- | --- |
| `UiProvider` | `strings`: the copy the components render when you pass no label, for translation: `confirm`, `cancel`, `close` (the screen-reader label of the dialog and sheet close button), `commandPaletteTitle`, `commandPaletteDescription`, and `chat` for the `ModelPicker` and `AgentPicker` copy (`defaultChatStrings` lists the keys and their English values; the session thread reads `i18n`). Pass only the keys you translate. `link`: the link component of your router, called with `href`. `useBrand`: a hook that returns your organization's logo URLs for `KortixLogo`. `image`: your image component. `navigation`: your router as four hooks (`useRouter`, `usePathname`, `useSearchParams`, `useParams`; a Next.js app passes the `next/navigation` hooks). `i18n`: your translation hooks (`useTranslations`, `useLocale`, the next-intl signatures) or `locale` + `messages`. `useViewerId`: a hook that returns the signed-in user's id. `config`: host flags (`billingEnabled`). `components`: the app features the thread opens but does not own (`ShareSessionModal`, `ProjectProviderModal`, `ProviderAccountsModal`, `ConnectorConnectModal`, `Wallpaper`). `UiProvider` also loads the animation features: without it, expanded rows stay closed. | English copy, a plain `<a>` and `<img>`, the Kortix logo, full page loads, no route params, the bundled English catalog of `@kortix/ui/i18n`, no viewer, billing off, no slots: a control that opens a missing slot is hidden. |
| `SessionIdsProvider` | `projectId` and `sessionId` of the session view it wraps. The session UI reads them with `useSessionIds`, never from your route. | Both ids are `undefined`: components that need them render nothing. |
| `setUiTelemetry` from `@kortix/ui/lib/telemetry` | Not a provider: call it once at module load with `track`, `captureException`, `captureMessage`, `addBreadcrumb`. Declare `UiTelemetryRegister { event: YourEvents }` to make `tsc` check event names. | `track` does nothing; `captureException` logs to the console. |
| `IconProvider` | Gives every Phosphor icon the Kortix weight and size. | Phosphor's defaults. |
| `<Toaster />` from `@kortix/ui/toast` | Renders the toasts that `successToast`, `errorToast` and the other helpers in `@kortix/ui/toast` raise. | No toast appears. |

## Theming

Every value a host is expected to vary is a CSS variable: colors in light and dark, the radius scale, border width, fonts, the type scale, spacing density, shadows and motion. Limits lists the few values that stay fixed. `@kortix/ui/theme` turns a typed theme object into those variables. Every field is optional. An unset field keeps the Kortix default, and a `dark` color falls back to the Kortix dark default, never to your `light` value.

### Bring your company brand in 10 lines

```tsx title="app/layout.tsx"
import { themeToCss, type KortixTheme } from '@kortix/ui/theme';

const brand: KortixTheme = {
  light: { blue: '#4f46e5', ring: '#4f46e5', border: '#e0e7ff' },
  dark: { blue: '#818cf8', ring: '#818cf8', border: '#312e81' },
  radius: '0.25rem',
  fonts: { sans: 'Inter, system-ui, sans-serif' },
};

// <html><head><style>{themeToCss(brand)}</style></head>…
```

`themeToCss` is a pure function, so it runs on the server and the first paint is already on brand. Its blocks out-rank `tokens.css`, so the `<style>` can sit anywhere in the page. The white-label demo does exactly this: `apps/whitelabel-demo/src/config/theme.ts` is its whole re-skin (indigo accent, indigo hairlines, a 4px radius, its own sans and mono stacks).

### The API

| Export | Signature | Use |
| --- | --- | --- |
| `KortixTheme` | `{ light?, dark?, radius?, spacing?, borderWidth?, fonts?, text?, lineHeights?, shadows?, durations?, easing?, vars? }` | The theme. `light` and `dark` take the color keys below plus any `--custom` variable. `vars` sets any other variable in both modes. An unknown field, color or step is a type error and throws at runtime. |
| `themeToCss` | `(theme: KortixTheme, selector = ':root') => string` | A stylesheet: light outside `.dark`, dark on or inside `.dark`. Pass a selector to theme one element. It throws on a value that contains `;`, `{`, `}`, `<`, `>`, `\` or a comment, and on a variable name other than `--[A-Za-z0-9_-]+`, so a theme built from tenant data cannot add CSS rules. |
| `themeToCssVars` | `(theme: KortixTheme) => { light: Record<string, string>; dark: Record<string, string> }` | The same variables as data, for a host that writes its own CSS or sets them from JavaScript. Mode-independent values appear in both. |
| `ThemeScope` | `<ThemeScope theme={…} className? {...divProps}>` | Themes one subtree: an embedded widget, a customer preview, a settings pane. Dialogs, popovers, menus, tooltips, selects, sheets and drawers opened inside it portal into a host at the end of `<body>` that carries the scope's theme, so they wear it too. |

```tsx title="A themed subtree"
import { ThemeScope } from '@kortix/ui/theme';

<ThemeScope theme={{ light: { primary: '#0f766e' }, radius: '1rem' }} className="bg-background">
  <SessionThread … />
</ThemeScope>
```

`ThemeScope` sets `font-family` and `color` on its element, because both inherit as computed values and would otherwise ignore the override. It paints no background; add `bg-background` when it should. Put `className="dark"` on it to force dark for the subtree. The scope element holds only your children: its `<style>` renders as the sibling just before it, and the overlay host lives in `<body>`. So `flex gap-*`, `grid`, `space-y-*` and `first:` / `last:` on its children behave as they would without the scope. Overlays are not clipped or offset by a `transform`, `filter`, `backdrop-filter`, `contain` or `overflow: hidden` ancestor of the scope, and a nested scope's overlays carry both themes.

Toasts do not portal: `<Toaster>` renders where it is mounted. To theme toasts, mount `<Toaster />` inside the `ThemeScope`, at its top level, not inside a transformed panel.

| `easing.default`, `in`, `out`, `inOut` | `--ease-*` | `ease-*` curves | the Kortix curves |
| `vars` | any `--name` | Anything else, for example `--liquid-glass-blur` | — |

### Limits

- An explicit width class (`border-2`, `border-[3px]`) stays fixed. Only bare `border*` and `divide-*` follow `borderWidth`.
- Font sizes with no step stay fixed: 10px, 11px and 12px captions (the card meta line, the attachment tile, code-block chrome) and the `0.8rem` inline code chip.
- Durations with no step stay fixed: `duration-80`, `duration-0`, the sidebar slide (`200` / `240` / `260ms` on `cubic-bezier(0.32, 0.72, 0, 1)`), the command palette (`140` / `180ms`) and the enter / exit keyframes (`200` / `250ms`). Every `duration-100` / `150` / `200` / `300` / `500` reads `duration-fast` … `duration-slower`.
- A `ThemeScope` can force dark inside a light page, not light inside a dark one: no `.light` reset exists, so `.dark` on `<html>` reaches the scope.
- Chat surfaces read the semantic tokens above: `muted` for the user bubble and code blocks, `card` and `border` for tool cards and questions, `mutedForeground` for captions. They have no tokens of their own.
- A few decorative values stay fixed: the dialog scrims (black at 20–85%), the `inverse` `Button` variant, the `Tag` status palette, the loader and dot-matrix gradients, and chart legend swatches.

### Rules

- Theme through tokens. Never fork or restyle a component: a forked copy stops receiving fixes.
- Pass your logo through `UiProvider useBrand`, so `KortixLogo` renders your marks.
- Do not load `fonts.css`: Roobert is for Kortix surfaces. Set `fonts.sans`.
- Plain CSS works too, after the `@kortix/ui` import. Put light values in `:root:not(.dark)` and dark values in `.dark`. A bare `:root` rule also matches `<html class="dark">` and, coming later than `tokens.css`, overrides the dark value. `themeToCss` writes these selectors for you.

| `@kortix/ui/terminal`, `@kortix/ui/browser` | `SessionTerminal`, `PtyTerminal`; `SessionBrowser` | a mounted `useSession` |
| `@kortix/ui/apps` | `AppPreview`, the frame pool, the App view model | none |
| `@kortix/ui/access`, `@kortix/ui/customize` | Sharing and roles (`AccessDialog`, `RoleSelect`, `PrincipalPicker`); the project configuration pages (`ConnectorsPage`, `AgentsPage`, `TriggersPage`, `SecretsPage`, `ModelsPage`, `SkillsPage`, `ProjectSettingsPage`) | `projectId` |

The full name list of every entry is in the package skill, `skills/kortix-ui/references/modules.md`. A deep path such as `@kortix/ui/session/thread/session-chat` resolves, but it has no semver: the Kortix web app reads deep paths while it moves to the entries. Import the entry.

## Add a chat

`SessionThread` renders the whole chat of one session from one [`useSession`](/docs/sdk/react#usesession) result. It is the thread the Kortix web app renders: the transcript, the streaming turn, tool rows, permission and question prompts, the send error, and the composer with attachments, slash commands, the model and agent pickers and Stop.

```tsx title="chat.tsx"
import { useSession } from '@kortix/sdk/react';
import { SessionThread } from '@kortix/ui/session';

export function Chat({ projectId, sessionId }: { projectId: string; sessionId: string }) {
  const session = useSession(projectId, sessionId);
  return (
    <div className="flex h-dvh flex-col">
      <SessionThread session={session} hideHeader />
    </div>
  );
}
```

The parent sets the height, and the thread fills it. Everything reads off `session`: there is no second chat hook and no transport to write. The host mounts `QueryClientProvider`, `UiProvider` and one `<Toaster />`. A control whose host feature is missing (a `UiProvider` `components` slot) is hidden, never dead.

| Prop | What it does |
| --- | --- |
| `session` | The `useSession(projectId, sessionId)` result. Required. |
| `hideHeader` | Hides the thread's title row. Use it when your page has its own header. |
| `readOnly` | Hides the composer: a transcript to read. |
| `className` | Classes on the thread's root. |

`@kortix/ui/session` also exports `ModelPicker` and `AgentPicker`: controlled pickers over a plain list, for a form outside a session such as a new-session form. `providerLabel` on `ModelPicker` relabels a provider (a white-label returns its own name for `model.providerID === 'kortix'`).

### Replace one tool row

Every built-in tool row registers when `@kortix/ui/session` loads. Register your own row for a tool name to replace it. The row gets `ToolProps`: `call` is the session-log tool call (`name`, `input`, `status`, `result`). `BasicTool` draws the standard row; `GenericTool` is the default row.

```tsx title="lookup-row.tsx"
import { BasicTool, ToolRegistry, type ToolProps } from '@kortix/ui/session';

function LookupRow({ call }: ToolProps) {
  return <BasicTool trigger={`Lookup ${(call.input as { query: string }).query}`} />;
}

ToolRegistry.register('lookup', LookupRow);
```

### Compose your own layout

The building blocks of the thread come from `@kortix/ui/session` and read the same providers: `UserMessage`, `ThrottledMarkdown` (streaming markdown that holds back half-written code fences and tables), `UnifiedMarkdown`, `ToolPartRenderer`, `SessionChatInput` (the composer), `ModelSelector`, `AgentSelector`, `SessionPermissionPrompt`, `QuestionPrompt`, `TurnErrorDisplay`, `SessionBusyIndicator` and `SessionStartingLoader`. The composer parts are in `@kortix/ui/composer`, the side panel (files, changes, audit) in `@kortix/ui/session-panel`, and the composed screens (thread plus side panel, project sidebar, sessions list) in `@kortix/ui/workspace`. See [Modules](#modules).

### Render the transcript yourself

To draw every part with your own components, skip `@kortix/ui/session` and use the headless kit in `@kortix/sdk/react`: `useChatTurns` and `renderParts`. `renderParts` requires one renderer per part kind, so a new kind fails your build, not your UI. See [Build a chat UI](/docs/sdk/react#build-a-chat-ui).

## Build a dashboard

A dashboard is three SDK hooks and one component: `useProjects` lists projects, `useProjectSessions` lists one project's sessions, and `SessionThread` renders the session `useSession` opens. The samples below compiled with `tsc --noEmit` and `vite build` in a fresh Vite + React 19 app that installed both packages from their packed tarballs, and ran against a live Kortix API.

<Steps>
<Step title="Create the client">
Create it once, at module scope. `getToken` runs on every call, so a key never sits in the bundle.

```ts title="src/kortix.ts"
import { createKortix } from '@kortix/sdk';

const TOKEN_KEY = 'kortix_token';

export function readToken(): string | null {
  try {
    return sessionStorage.getItem(TOKEN_KEY);
  } catch {
    return null;
  }
}

export function saveToken(token: string): void {
  sessionStorage.setItem(TOKEN_KEY, token.trim());
}

// One client per host, created once at module scope. Every @kortix/sdk/react
// hook and every @kortix/ui/session component reads it.
export const kortix = createKortix({
  backendUrl: import.meta.env.VITE_KORTIX_API_URL ?? 'https://api.kortix.com/v1',
  getToken: async () => readToken(),
});
```

The browser origin must be in the API's CORS list. In local development, proxy `/v1` through your dev server and point `backendUrl` at it. Inside a [Kortix App](/docs/apps), the client acts as the viewer: run `kortix apps access <app> --viewer api`, then `createKortix({ backendUrl: '/_kortix/api/v1', getToken: kortixAppViewerToken() })`.
</Step>
<Step title="Mount the providers and your theme">
```tsx title="src/providers.tsx"
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { UiProvider } from '@kortix/ui';
import { IconProvider } from '@kortix/ui/icon-provider';
import { themeToCss } from '@kortix/ui/theme';
import { Toaster } from '@kortix/ui/toast';
import { useState, type ReactNode } from 'react';

import './kortix';
import { acmeTheme } from './theme';

const themeCss = themeToCss(acmeTheme);

export function Providers({ children }: { children: ReactNode }) {
  const [queryClient] = useState(() => new QueryClient());
  return (
    <QueryClientProvider client={queryClient}>
      {/* No props: plain <a> links, full page loads, the English catalog. */}
      <UiProvider>
        <IconProvider>
          <style href="acme-theme" precedence="default">{themeCss}</style>
          {children}
          <Toaster />
        </IconProvider>
      </UiProvider>
    </QueryClientProvider>
  );
}
```

React 19 hoists `<style href precedence>` into `<head>`. `acmeTheme` is a `KortixTheme` (see [Theming](#theming)): for example a teal `blue` and `ring`, `radius: '0.25rem'`, `borderWidth: '2px'` and `fonts.sans`.
</Step>
<Step title="List projects and sessions, open one">
```tsx title="src/dashboard.tsx"
import { generateSessionId } from '@kortix/sdk';
import { useProjectSessions, useProjects, useSession } from '@kortix/sdk/react';
import { Badge, Button, Card, CardContent, CardHeader, CardTitle } from '@kortix/ui';
import { Empty, EmptyDescription, EmptyHeader, EmptyTitle } from '@kortix/ui/empty';
import Loading from '@kortix/ui/loading';
import { SessionThread } from '@kortix/ui/session';
import { errorToast } from '@kortix/ui/toast';
import { useState } from 'react';

import { kortix } from './kortix';

export function Dashboard() {
  const projects = useProjects();
  const [picked, setPicked] = useState<string>();
  const projectId = picked ?? projects.data?.[0]?.project_id;
  const [sessionId, setSessionId] = useState<string>();

  return (
    <div className="grid h-dvh grid-cols-[18rem_1fr] bg-background text-foreground">
      <aside className="flex min-h-0 flex-col gap-4 overflow-y-auto border-r p-4">
        <h1 className="text-lg font-medium">Acme Agents</h1>
        <Card>
          <CardHeader>
            <CardTitle>Projects</CardTitle>
          </CardHeader>
          <CardContent className="flex flex-col gap-1">
            {projects.isLoading && <Loading />}
            {projects.data?.map((project) => (
              <Button
                key={project.project_id}
                variant={project.project_id === projectId ? 'secondary' : 'ghost'}
                className="justify-start"
                onClick={() => {
                  setPicked(project.project_id);
                  setSessionId(undefined);
                }}
              >
                {project.name}
              </Button>
            ))}
          </CardContent>
        </Card>
        {projectId && <SessionList projectId={projectId} selected={sessionId} onSelect={setSessionId} />}
      </aside>
      <main className="min-h-0">
        {projectId && sessionId ? (
          <Thread key={sessionId} projectId={projectId} sessionId={sessionId} />
        ) : (
          <Empty className="h-full">
            <EmptyHeader>
              <EmptyTitle>No session open</EmptyTitle>
              <EmptyDescription>Pick a session or start a new one.</EmptyDescription>
            </EmptyHeader>
          </Empty>
        )}
      </main>
    </div>
  );
}

function SessionList({
  projectId,
  selected,
  onSelect,
}: {
  projectId: string;
  selected?: string;
  onSelect: (sessionId: string) => void;
}) {
  const { sessions, isLoading, refetch } = useProjectSessions(projectId, { limit: 20 });
  const [creating, setCreating] = useState(false);

  async function startSession() {
    setCreating(true);
    try {
      const sessionId = generateSessionId();
      await kortix.project(projectId).sessions.create({ session_id: sessionId, name: 'Dashboard session' });
      await refetch();
      onSelect(sessionId);
    } catch (error) {
      errorToast('Could not start a session', { description: error instanceof Error ? error.message : undefined });
    } finally {
      setCreating(false);
    }
  }

  return (
    <Card>
      <CardHeader>
        <CardTitle>Sessions</CardTitle>
      </CardHeader>
      <CardContent className="flex flex-col gap-1">
        <Button variant="brand" disabled={creating} onClick={startSession}>
          New session
        </Button>
        {isLoading && <Loading />}
        {sessions.map((session) => (
          <Button
            key={session.session_id}
            variant={session.session_id === selected ? 'secondary' : 'ghost'}
            className="justify-between"
            onClick={() => onSelect(session.session_id)}
          >
            <span className="truncate">{session.name ?? session.branch_name}</span>
            <Badge size="sm" variant="muted">
              {session.status}
            </Badge>
          </Button>
        ))}
      </CardContent>
    </Card>
  );
}

// useSession owns the whole session: start, the live stream, the transcript.
function Thread({ projectId, sessionId }: { projectId: string; sessionId: string }) {
  const session = useSession(projectId, sessionId);
  return <SessionThread session={session} hideHeader />;
}
```
</Step>
</Steps>

- `useProjectSessions` does not poll. Pass `refetchInterval` (ms) to keep each `status` fresh.
- More data for a dashboard: `useProjectApps`, `useProjectTriggers`, `useChangeRequests`, `useGatewayOverview` and `useCan` ([Hooks](/docs/sdk/react#hooks)).
- Never `fetch` the Kortix API yourself. If the SDK lacks a call you need, that is an SDK gap to report.
