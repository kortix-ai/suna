title: Kortix UI
description: "@kortix/ui: the Kortix React components and the session chat, themed by CSS variables, for your own app."
---

`@kortix/ui` is the React component library that the Kortix web app renders, and the whole Kortix session experience as modules: the session workspace (thread plus side panel), the composer, files and the file viewer, the terminal, the project home and the session list. The same package serves Kortix Apps, white-label hosts and your own app, so a button, a chat thread or a session screen looks and behaves the same everywhere. Components are Tailwind CSS v4 class strings that read CSS variables. You re-theme them with a typed theme (`@kortix/ui/theme`) or by overriding the variables, never by copying a component.

<Callout type="warning">
`@kortix/ui` is not on npm yet. Today it is a workspace package of the [kortix-ai/suna](https://github.com/kortix-ai/suna) repository: inside that repository, add `"@kortix/ui": "workspace:*"` to your package's dependencies. This page describes the package as it ships there.
</Callout>

Server rendering: the entries that render sessions or files (`session`, `composer`, `session-panel`, `workspace`, `files`, `file-viewer`, `markdown`, `genui`, `customize`) import CSS (KaTeX and others) from JS, so plain Node cannot evaluate them (`ERR_UNKNOWN_FILE_EXTENSION ".css"`). </Callout>

## Add the styles

Load the styles once, in your app's main stylesheet or entry file. Pick the row for your host.

<Tabs>
<Tab title="Tailwind CSS v4 host">
Import `@kortix/ui/tailwind.css` after Tailwind. It brings the tokens (`tokens.css`), the component layer (`theme.css`: the `dark` variant, the `@theme` keys the component classes resolve against, the utilities and the keyframes), the animation utilities and the scrollbar plugins. `theme.css` also adds an `@source` rule, so Tailwind scans the package for class names.

```css title="app.css"
@import 'tailwindcss';
@import '@kortix/ui/tailwind.css';
```

Your own classes resolve against the same tokens: `bg-background`, `text-muted-foreground`, `border-border`.

<Callout type="warning">
`tokens.css` sets `--spacing: 0.23rem`, 8% tighter than Tailwind's `0.25rem`. Your own spacing utilities follow it: `p-4` is 14.72px, not 16px. To keep stock Tailwind spacing for your own classes, set `--spacing: 0.25rem` in `:root` after the import. The components then render 8% larger.
</Callout>

To bring your own token values instead of `tokens.css`, import the parts one by one. Every line except `tokens.css` is required: without `tw-animate-css` and the two plugins, overlays lose their enter and exit animations and `scrollbar-hide` does nothing, and the build reports no error.

```css title="app.css"
@import 'tailwindcss';
@import 'tw-animate-css';
@import '@kortix/ui/tokens.css'; /* optional: or set every variable yourself */
@import '@kortix/ui/theme.css';
@plugin 'tailwind-scrollbar';
@plugin 'tailwind-scrollbar-hide';
```
</Tab>
<Tab title="Host without Tailwind">
Import one prebuilt file. It holds the reset, the tokens and every class the components use.

```ts title="main.tsx"
import '@kortix/ui/styles.css';
```

It holds no class that only your own code uses. Style your own markup with plain CSS that reads the variables, such as `var(--border)`.
</Tab>
</Tabs>

- Dark mode is the `dark` class on `<html>`. Add or remove it to switch themes. `useIsDark()` returns the current state.
- Both paths style the page itself: `body` paints `--background` and `--foreground`, borders default to `--border`, native controls follow the theme (`color-scheme`), text selection reads `--selection`, and interactive elements show the pointer cursor. You add no base rules of your own.
- `@kortix/ui/fonts.css` loads the Roobert font, for Kortix-owned surfaces only. Every other host renders the system font stack (`--font-sans-system`).

## Mount the providers

Mount these once, at the root of your app:

```tsx title="providers.tsx"
import { UiProvider, type UiLinkComponent } from '@kortix/ui';
import { IconProvider } from '@kortix/ui/icon-provider';
import { Toaster } from '@kortix/ui/toast';
import { Link } from 'react-router-dom';

// Any router: `UiProvider` passes anchor props with `href` and a Next.js-style `prefetch` hint.
const RouterLink: UiLinkComponent = ({ href, prefetch: _prefetch, ...props }) => <Link to={href} {...props} />;

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <UiProvider strings={{ confirm: 'Confirm', cancel: 'Cancel' }} link={RouterLink}>
      <IconProvider>
        {children}
        <Toaster />
      </IconProvider>
    </UiProvider>
  );
}
```

| Provider | What it does | Without it |
| --- | --- | --- |
| `UiProvider` | `strings`: the copy the components render when you pass no label, for translation: `confirm`, `cancel`, `close` (the screen-reader label of the dialog and sheet close button), `commandPaletteTitle`, `commandPaletteDescription` (the session UI reads `i18n`). Pass only the keys you translate. `link`: the link component of your router, called with `href`. `useBrand`: a hook that returns your organization's logo URLs for `KortixLogo`. `image`: your image component. `navigation`: your router as four hooks (`useRouter`, `usePathname`, `useSearchParams`, `useParams`; a Next.js app passes the `next/navigation` hooks). `i18n`: your translation hooks (`useTranslations`, `useLocale`, the next-intl signatures) or `locale` + `messages`. `useViewerId`: a hook that returns the signed-in Kortix user's id. Without it, a one-person session names no sender and a stopped turn never says "Stopped by"; a session several people write in needs it. `components`: the app features the session UI opens but does not own (`ShareSessionModal`, which `@kortix/ui/workspace` exports; `HomeAnnouncement`, `ProjectProviderModal`, `ProviderAccountsModal`, `ConnectorConnectModal`, `Wallpaper`). `config`: `managedModelsEnabled` for a deployment that serves its model lineup, `connectorsEnabled`. `config.terminalEnabled` (default true): false hides the Terminal, for a host whose proxy cannot upgrade a WebSocket. `config.commandPaletteShortcut` and `config.settingsShortcut` (default false): true when the host opens a command palette on ⌘K or settings on ⌘,; only then does the composer hint at them. `config.providerIconBaseUrl`: where the host serves provider logos (`<base>/<icon>.svg`); without it they load from models.dev, and the Kortix provider draws `useBrand`'s icon. `resolvePreviewUrl`: a function that returns the URL the session browser frames, with the host's own scoped credentials (for a host whose origin is not the Kortix backend, or whose browser must not hold a Kortix token); null or no function keeps the SDK preview URL. Billing is the SDK flag `configureKortix({ billingEnabled })`, which every billing gate reads. It is for Kortix's own app: its upgrade actions open the Kortix plan dialog that apps/web mounts. A custom host leaves it off, so no upgrade control renders. `UiProvider` also loads the animation features: without it, expanded rows stay closed. | English copy, a plain `<a>` and `<img>`, the Kortix logo, full page loads, no route params, the bundled English catalog of `@kortix/ui/i18n`, no viewer, billing off, no managed model lineup, no slots: a control that opens a missing slot is hidden. |
| `SessionIdsProvider` | `projectId` and `sessionId` of the view it wraps. The session UI reads them with `useSessionIds`, never from your route. `SessionThread`, `SessionWorkspace` and `ProjectHome` mount it themselves, with the SDK's project scope. Around any other block, mount it inside `KortixProjectProvider` from `@kortix/sdk/react`. | Both ids are `undefined`: components that need them render nothing. |
| `setUiTelemetry` from `@kortix/ui/lib/telemetry` | Not a provider: call it once at module load with `track`, `captureException`, `captureMessage`, `addBreadcrumb`. Declare `UiTelemetryRegister { event: YourEvents }` to make `tsc` check event names. | `track` does nothing; `captureException` logs to the console. |
| `IconProvider` | Gives every Phosphor icon the Kortix weight and size. | Phosphor's defaults. |
| `<Toaster />` from `@kortix/ui/toast` | Renders the toasts that `successToast`, `errorToast` and the other helpers in `@kortix/ui/toast` raise. | No toast appears. |

## Routes

Every URL the components link to comes from one route table, `setUiRoutes` (`@kortix/ui`), called once at module load. The defaults are Kortix's own paths: `project` `/projects/<id>`, `session` `/projects/<id>/sessions/<sessionId>`, `sessions` `/projects/<id>/sessions` (`?view=archived|deleted`), `files` `/projects/<id>/files`, `drive` `/projects/<id>/drive`, `apps` `/projects/<id>/apps`, `members` `/projects/<id>/members`, `sandboxSettings` `/projects/<id>/config?section=sandbox`, `customize` `/projects/<id>/customize/<page>` (agents, skills, connectors, triggers, reminders, models, secrets, review, settings). Return your own path for a page you serve elsewhere. Return `null` for a page you do not serve: every link to it is hidden. `project` and `session` cannot be null.

```ts
import { setUiRoutes } from '@kortix/ui';

setUiRoutes({
  session: (projectId, sessionId) => `/w/${projectId}/chat/${sessionId}`,
  drive: () => null,
  customize: () => null,
});
```

## Theming

Every value a host is expected to vary is a CSS variable: colors in light and dark, the radius scale, border width, fonts, the type scale, spacing density, shadows and motion. Limits lists the few values that stay fixed. `@kortix/ui/theme` turns a typed theme object into those variables. Every field is optional. An unset field keeps the Kortix default, and a `dark` color falls back to the Kortix dark default, never to your `light` value.

### Bring your company brand in 10 lines

```tsx title="app/layout.tsx"
import { themeToCss, type KortixTheme } from '@kortix/ui/theme';

const brand: KortixTheme = {
  light: { blue: '#4f46e5', ring: '#4f46e5', border: '#e0e7ff' },
  dark: { blue: '#818cf8', ring: '#818cf8', border: '#312e81' },
  radius: '0.25rem',
  fonts: { sans: 'Inter, system-ui, sans-serif' },
};

// <html><head><style>{themeToCss(brand)}</style></head>…
```

`themeToCss` is a pure function, so it runs on the server and the first paint is already on brand. Its blocks out-rank `tokens.css`, so the `<style>` can sit anywhere in the page. The white-label demo does exactly this: `apps/whitelabel-demo/src/config/theme.ts` is its whole re-skin (indigo accent, indigo hairlines, a 4px radius, its own sans and mono stacks).

### The API

| Export | Signature | Use |
| --- | --- | --- |
| `KortixTheme` | `{ light?, dark?, radius?, spacing?, borderWidth?, fonts?, text?, lineHeights?, shadows?, durations?, easing?, vars? }` | The theme. `light` and `dark` take the color keys below plus any `--custom` variable. `vars` sets any other variable in both modes. An unknown field, color or step is a type error and throws at runtime. |
| `themeToCss` | `(theme: KortixTheme, selector = ':root') => string` | A stylesheet: light outside `.dark`, dark on or inside `.dark`. Pass a selector to theme one element. It throws on a value that contains `;`, `{`, `}`, `<`, `>`, `\` or a comment, and on a variable name other than `--[A-Za-z0-9_-]+`, so a theme built from tenant data cannot add CSS rules. |
| `themeToCssVars` | `(theme: KortixTheme) => { light: Record<string, string>; dark: Record<string, string> }` | The same variables as data, for a host that writes its own CSS or sets them from JavaScript. Mode-independent values appear in both. |
| `ThemeScope` | `<ThemeScope theme={…} className? {...divProps}>` | Themes one subtree: an embedded widget, a customer preview, a settings pane. Dialogs, popovers, menus, tooltips, selects, sheets and drawers opened inside it portal into a host at the end of `<body>` that carries the scope's theme, so they wear it too. |

```tsx title="A themed subtree"
import { ThemeScope } from '@kortix/ui/theme';

<ThemeScope theme={{ light: { primary: '#0f766e' }, radius: '1rem' }} className="bg-background">
  <SessionThread … />
</ThemeScope>
```

`ThemeScope` sets `font-family` and `color` on its element, because both inherit as computed values and would otherwise ignore the override. It paints no background; add `bg-background` when it should. Put `className="dark"` on it to force dark for the subtree. The scope element holds only your children: its `<style>` renders as the sibling just before it, and the overlay host lives in `<body>`. So `flex gap-*`, `grid`, `space-y-*` and `first:` / `last:` on its children behave as they would without the scope. Overlays are not clipped or offset by a `transform`, `filter`, `backdrop-filter`, `contain` or `overflow: hidden` ancestor of the scope, and a nested scope's overlays carry both themes.

Toasts do not portal: `<Toaster>` renders where it is mounted. To theme toasts, mount `<Toaster />` inside the `ThemeScope`, at its top level, not inside a transformed panel.

### Limits

- An explicit width class (`border-2`, `border-[3px]`) stays fixed. Only bare `border*` and `divide-*` follow `borderWidth`.
- Font sizes with no step stay fixed: 10px, 11px and 12px captions (the card meta line, the attachment tile, code-block chrome) and the `0.8rem` inline code chip.
- Durations with no step stay fixed: `duration-80`, `duration-0`, the sidebar slide (`200` / `240` / `260ms` on `cubic-bezier(0.32, 0.72, 0, 1)`), the command palette (`140` / `180ms`) and the enter / exit keyframes (`200` / `250ms`). Every `duration-100` / `150` / `200` / `300` / `500` reads `duration-fast` … `duration-slower`.
- A `ThemeScope` can force dark inside a light page, not light inside a dark one: no `.light` reset exists, so `.dark` on `<html>` reaches the scope.
- Chat surfaces read the semantic tokens above: `muted` for the user bubble and code blocks, `card` and `border` for tool cards and questions, `mutedForeground` for captions. They have no tokens of their own.
- A few decorative values stay fixed: the dialog scrims (black at 20–85%), the `inverse` `Button` variant, the `Tag` status palette, the loader and dot-matrix gradients, and chart legend swatches.

### Rules

- Theme through tokens. Never fork or restyle a component: a forked copy stops receiving fixes.
- Pass your logo through `UiProvider useBrand`, so `KortixLogo` renders your marks.
- Do not load `fonts.css`: Roobert is for Kortix surfaces. Set `fonts.sans`.
- Plain CSS works too, after the `@kortix/ui` import. Put light values in `:root:not(.dark)` and dark values in `.dark`. A bare `:root` rule also matches `<html class="dark">` and, coming later than `tokens.css`, overrides the dark value. `themeToCss` writes these selectors for you.

| Layout | `Card`, `Section`, `Tabs`, `Disclosure`, `Accordion`, `Separator`, `ScrollArea` | `card`, `section`, `tabs`, `disclosure`, `accordion`, `separator`, `scroll-area` | [Card](https://kortix.com/design-system#comp-card), [Tabs](https://kortix.com/design-system#comp-tabs), [Accordion](https://kortix.com/design-system#comp-accordion) |
| Data | `Table`, `DefinitionList`, `InlineMeta`, `Empty`, `Calendar` | `table`, `definition-list`, `inline-meta`, `empty`, `calendar` | [Table](https://kortix.com/design-system#comp-table), [DefinitionList](https://kortix.com/design-system#pat-definition-list), [InlineMeta](https://kortix.com/design-system#pat-inline-meta) |
| People | `UserAvatar`, `EntityAvatar` | `user-avatar`, `entity-avatar` | [Avatars](https://kortix.com/design-system#pat-avatars) |

Compose before you create. Use `Modal` for a dialog, `Hint` for a tooltip, `Loading` for a spinner, `Badge` for a chip and `ConfirmDialog` before a destructive action. Never call `sonner`'s `toast()` directly, and never use an icon with `animate-spin` as a spinner. Icons come from `@phosphor-icons/react`.

## Modules

Every part of a Kortix session is a module with one entry. Each entry is a curated list of names: that list is the public API, under semver. Every piece needs `UiProvider` and a `QueryClientProvider` at the root.

| Entry | What it is | Minimal mount |
| --- | --- | --- |
| `@kortix/ui/workspace` | Composed project screens: `SessionWorkspace` (thread plus resizable side panel), `ProjectHome` (the new-session composer; it sends by itself), `ProjectSessionList`, `ProjectSessionsView`, `ProjectFilesView`, `ProjectSidebar`, `ShareSessionModal` | `<SessionWorkspace session={useSession(projectId, sessionId)} />`, `<ProjectHome projectId={projectId} />`; `ProjectSessionList` inside a `SidebarProvider` |
| `@kortix/ui/session` | The conversation: `SessionThread`, turns, tool rows and `ToolRegistry`, prompts, status, `ModelSelector`, `AgentSelector` | `<SessionThread session={useSession(projectId, sessionId)} />` |
| `@kortix/ui/composer` | The message composer: `ComposerChatInput`, `SessionChatInput`, its chrome, the editor parts, the send pipeline | `<ComposerChatInput projectId={projectId} onSend={…} />` in the project scope |
| `@kortix/ui/session-panel` | The side panel: `SessionPanelProvider`, `ActionPanel`, `SessionFiles`, `SessionChanges`, `SessionAudit`, `openSessionQuickView` | `SessionPanelProvider` (runtime `sessionId`, `projectId`, `projectSessionId`) |
| `@kortix/ui/files` | Project files (the git-backed repo: `ProjectFilesProvider`, `FileExplorerPage`, `DriveExplorer`), sandbox files (`SandboxFileExplorer`), `FilePreviewHost`, drive and change-request hooks | `ProjectFilesView` from `workspace`; `<FilePreviewHost />` once on a page without a side panel |
| `@kortix/ui/file-viewer` | `FileViewer` and `FileContentRenderer` for any file kind (pdf, docx, xlsx, csv, pptx, zip, images, code), `FilePreviewModal`, `FileSourceProvider` | `<FileViewer content={text} fileName="notes.md" />` |
| `@kortix/ui/terminal`, `@kortix/ui/browser` | `SessionTerminal`; `SessionBrowser`, `BrowserLanding` | the runtime ids of a mounted `useSession` |
| `@kortix/ui/markdown`, `@kortix/ui/genui` | `UnifiedMarkdown`, `MarkdownWithFrontmatter`, `HighlightedCode`; typed UI blocks in assistant text | `<UnifiedMarkdown content={text} trust="agent" />` |
| `@kortix/ui/diff`, `@kortix/ui/changes` | `DiffView`; `ChangeList` with its vocabulary | `<DiffView before={…} after={…} />` |
| `@kortix/ui/apps` | `AppPreview`, the frame pool, the App view model | none |
| `@kortix/ui/access`, `@kortix/ui/customize` | Sharing and roles (`AccessDialog`, `RoleSelect`, `PrincipalPicker`); the project configuration pages (`ConnectorsPage`, `AgentsPage`, `TriggersPage`, `SecretsPage`, `ModelsPage`, `SkillsPage`, `ProjectSettingsPage`) | `<ConnectorsPage projectId={projectId} />` |
| `@kortix/ui/theme`, `@kortix/ui/i18n`, `@kortix/ui/icons` | The typed theme; `useTranslations`, `useLocale` (next-intl signatures); the library's glyphs | none |

The package skill lists every name of every entry, its props and one example that compiles: `skills/kortix-ui/references/modules.md`.

### Deep paths have no semver

The entries and the primitive subpaths (`@kortix/ui/<component>`) are the public API. A few deep paths also resolve: `@kortix/ui/internal/*` and `@kortix/ui/<module>/<path>`, such as `@kortix/ui/session/thread/session-chat`. They exist only for Kortix's own apps (the list is `scripts/deep-exports.json`), and they can change or disappear in any release. Import the entry. If an entry lacks a name you need, ask for it to be added to the entry.

## Add a session

`SessionWorkspace` (`@kortix/ui/workspace`) renders the whole session screen of the Kortix web app from one [`useSession`](/docs/sdk/react#usesession) result: the thread, and the resizable side panel its actions open (files, the file viewer, the browser, the terminal, changes). On a phone the panel is a sheet.

```tsx title="session.tsx"
import { useSession } from '@kortix/sdk/react';
import { SessionWorkspace } from '@kortix/ui/workspace';

export function Session({ projectId, sessionId }: { projectId: string; sessionId: string }) {
  return <SessionWorkspace session={useSession(projectId, sessionId)} />;
}
```

`SessionWorkspace` takes `session`, `children` (your own column in place of the thread), `hideHeader`, `readOnly` and `className`. The parent sets the size.

### The thread alone

`SessionThread` renders the whole chat of one session from one [`useSession`](/docs/sdk/react#usesession) result. It is the thread the Kortix web app renders: the transcript, the streaming turn, tool rows, permission and question prompts, the send error, and the composer with attachments, slash commands, the model and agent pickers and Stop.

```tsx title="chat.tsx"
import { useSession } from '@kortix/sdk/react';
import { SessionThread } from '@kortix/ui/session';

export function Chat({ projectId, sessionId }: { projectId: string; sessionId: string }) {
  const session = useSession(projectId, sessionId);
  return (
    <div className="flex h-dvh flex-col">
      <SessionThread session={session} hideHeader />
    </div>
  );
}
```

The parent sets the height, and the thread fills it. Everything reads off `session`: there is no second chat hook and no transport to write. The host mounts `QueryClientProvider`, `UiProvider` and one `<Toaster />`. A control whose host feature is missing (a `UiProvider` `components` slot) is hidden, never dead. With no side panel on the page, a file or preview the thread opens shows in a dialog.

| Prop | What it does |
| --- | --- |
| `session` | The `useSession(projectId, sessionId)` result. Required. |
| `hideHeader` | Hides the thread's title row. Use it when your page has its own header. |
| `readOnly` | Hides the composer: a transcript to read. |
| `className` | Classes on the thread's root. |

`@kortix/ui/session` also exports `ModelSelector` and `AgentSelector`, the composer's pickers. They are controlled (`models` or `agents`, the selection, `onSelect`), so a form outside a session, such as a new-session form, uses them too.

### Replace one tool row

Every built-in tool row registers when `@kortix/ui/session` loads. Register your own row for a tool name to replace it. The row gets `ToolProps`: `call` is the session-log tool call (`name`, `input`, `status`, `result`). `BasicTool` draws the standard row; `GenericTool` is the default row.

```tsx title="src/shell-row.tsx"
import { BasicTool, ToolRegistry, type ToolProps } from '@kortix/ui/session';
import { TerminalWindowIcon } from '@phosphor-icons/react';

// Replaces the built-in row of the `bash` tool. A later register() for the same
// name wins; @kortix/ui/session registers its rows on import.
function ShellRow({ call }: ToolProps) {
  const command = (call.input as { command?: string } | null)?.command ?? '';
  const output = (call.result?.content ?? [])
    .map((part) => (part.type === 'text' ? part.text : ''))
    .join('');
  return (
    <BasicTool icon={<TerminalWindowIcon />} trigger={{ title: 'Shell', subtitle: command }}>
      <pre data-testid="acme-shell-output" className="bg-muted overflow-x-auto rounded-md p-3 font-mono text-xs">
        {output || 'No output yet'}
      </pre>
    </BasicTool>
  );
}

ToolRegistry.register('bash', ShellRow);
```

Import the file once at your entry (`import './shell-row'`). `call.status` is `pending`, `running`, `complete` or `error`; `call.result.content` holds the text and attachment parts.

### Compose a custom workspace

The modules compose at any depth. Pick the level you need:

| You want | Use |
| --- | --- |
| Kortix's session screen in your chrome | `SessionWorkspace` |
| Your own conversation column beside Kortix's side panel | `<SessionWorkspace session={session}>{yourColumn}</SessionWorkspace>` |
| The thread, no panel | `SessionThread`; a page with neither mounts `<FilePreviewHost />` from `@kortix/ui/files` once |
| Your own panel | `SessionPanelProvider` + `ActionPanel` from `@kortix/ui/session-panel`, or `SessionTerminal` from `@kortix/ui/terminal` |
| Single blocks | `UserMessage`, `ThrottledMarkdown`, `ToolPartRenderer`, `ModelSelector`, `AgentSelector`, `SessionPermissionPrompt`, `QuestionPrompt` from `@kortix/ui/session`; `ComposerChatInput` from `@kortix/ui/composer` |

A block outside `SessionThread`, `SessionWorkspace` and `ProjectHome` needs the two scopes those screens mount for you:

```tsx title="ask.tsx"
import { KortixProjectProvider } from '@kortix/sdk/react';
import { SessionIdsProvider } from '@kortix/ui';
import { ComposerChatInput } from '@kortix/ui/composer';

// The composer alone, before a session exists: you decide what a send does.
// Outside SessionThread / SessionWorkspace / ProjectHome, mount the two scopes
// they mount for you: the SDK's project (model catalog) and the UI's ids.
export function Ask({ projectId, onAsk }: { projectId: string; onAsk: (text: string) => void }) {
  return (
    <KortixProjectProvider projectId={projectId}>
      <SessionIdsProvider projectId={projectId}>
        <ComposerChatInput projectId={projectId} onSend={(text) => onAsk(text)} />
      </SessionIdsProvider>
    </KortixProjectProvider>
  );
}
```

### Render the transcript yourself

To draw every part with your own components, skip `@kortix/ui/session` and use the headless kit in `@kortix/sdk/react`: `useChatTurns` and `renderParts`. `renderParts` requires one renderer per part kind, so a new kind fails your build, not your UI. See [Build a chat UI](/docs/sdk/react#build-a-chat-ui).

## Build a dashboard

A dashboard is your chrome around the composed screens: Kortix's session list in your sidebar, `ProjectHome` to start a session, `SessionWorkspace` to work in one, `ProjectFilesView` for the project's files. The steps below are files of one Vite + React 19 + react-router app that installed both packages from their packed tarballs. It passed `tsc --noEmit` and `vite build` and ran against a live Kortix API: a prompt from the home opened the session, the tool rows (the custom one included) and the reply rendered, a file opened in the side panel and on the Files page, with 0 console errors.

<Step title="Create the client">
Create it once, at module scope. `getToken` runs on every call, so a key never sits in the bundle.

```ts title="src/kortix.ts"
import { createKortix } from '@kortix/sdk';

const TOKEN_KEY = 'kortix_token';

export function readToken(): string | null {
  try {
    return sessionStorage.getItem(TOKEN_KEY);
  } catch {
    return null;
  }
}

export function saveToken(token: string): void {
  sessionStorage.setItem(TOKEN_KEY, token.trim());
}

// One client per host, created once at module scope. Every @kortix/sdk/react
// hook and every @kortix/ui/session component reads it.
export const kortix = createKortix({
  backendUrl: import.meta.env.VITE_KORTIX_API_URL ?? 'https://api.kortix.com/v1',
  getToken: async () => readToken(),
});
```

The browser origin must be in the API's CORS list. In local development, proxy `/v1` through your dev server and point `backendUrl` at it. Inside a [Kortix App](/docs/apps), the client acts as the viewer: run `kortix apps access <app> --viewer api`, then `createKortix({ backendUrl: '/_kortix/api/v1', getToken: kortixAppViewerToken() })`.

import type { UiLinkComponent, UiNavigation, UiRouter } from '@kortix/ui';
import { useMemo } from 'react';
import { Link, useLocation, useNavigate, useParams, useSearchParams } from 'react-router-dom';

// @kortix/ui links and router calls go through your router, not full page loads.
export const RouterLink: UiLinkComponent = ({ href, prefetch: _prefetch, ...props }) => (
  <Link to={href} {...props} />
);

function useUiRouterAdapter(): UiRouter {
  const navigate = useNavigate();
  return useMemo(
    () => ({
      push: (href) => navigate(href),
      replace: (href) => navigate(href, { replace: true }),
      prefetch: () => {},
      back: () => navigate(-1),
    }),
    [navigate],
  );
}

export const navigation: UiNavigation = {
  useRouter: useUiRouterAdapter,
  usePathname: () => useLocation().pathname,
  useSearchParams: () => useSearchParams()[0],
  useParams: () => useParams(),
};
