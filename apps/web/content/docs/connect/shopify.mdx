title: Shopify
description: Connect a Shopify store and give agents its orders, customers, products and inventory through the Admin API.
---

The Shopify connector (`provider: shopify`) calls a store's Admin GraphQL API. Each account is one store. You approve the app once in Shopify, and the token does not expire.

## Why your own app

Shopify gives orders and customers (protected customer data) only to an app that it approved for them. A public app needs Shopify's review. An app with **Custom distribution** for your store has the access at once, without review. So you connect with a Shopify app that you create for the store.

If this Kortix deployment has a shared Shopify app, Connect asks only for the store.

## Create the app in Shopify

1. In the [Shopify Dev Dashboard](https://dev.shopify.com/dashboard), create an app in the organization that owns the store.
2. In the app version, add the redirect URL and the Admin API scopes, then release the version:

   ```text
   https://api.kortix.com/v1/connectors/shopify/callback
   ```

   On a self-hosted instance the URL is `<KORTIX_URL>/v1/connectors/shopify/callback`. The Connect form shows the exact URL for your deployment.

   The default scopes are `read_orders`, `write_orders`, `read_draft_orders`, `write_draft_orders`, `read_products`, `write_products`, `read_customers`, `write_customers`, `read_inventory`, `write_inventory` and `read_locations`.
3. Under **Distribution**, choose **Custom distribution** and select the store.
4. Install the app on the store.
5. From the app's **Settings**, copy the **Client ID** and the **Client secret**.

## Connect

From the web app: **Customize → Connectors**, choose **Shopify** in the catalogue, then **Install**. The connector page opens **Add account**. Continue, and a window opens the Kortix form. The form asks for the store (`acme` for `acme.myshopify.com`), the Client ID and the Client secret, and shows the redirect URL and the scopes. Then Shopify asks you to approve the app, and the form shows what the account can read.

From a terminal:

```bash
kortix connectors add shopify --provider shopify --shop acme --apply
kortix connectors connect shopify          # prints the form link
kortix connectors call shopify graphql '{"query":"{ shop { name } }"}'
```

In `kortix.yaml`:

```yaml
connectors:
  - slug: shopify
    provider: shopify
    name: Shopify
    shop: acme.myshopify.com   # the store Connect offers; optional
    scopes:                    # optional; omit for the default scopes
      - read_orders
      - read_products
```

- Kortix keeps the client secret and the token on the account, encrypted. Neither goes into `kortix.yaml` or git.
- The token belongs to the store that approved it. A call always goes to that store.
- To connect another store, add another account: each account is one store. With two accounts and no default, a call needs `--account <store>` and is otherwise denied with `account_required`.
- A `scopes` list on the connector replaces the default scopes for every account's Connect.

## What the connector does

| Action | What it does |
| --- | --- |
| `graphql` | Runs any Admin GraphQL query or mutation. Shopify blocks introspection, so write the document from the [Admin API reference](https://shopify.dev/docs/api/admin-graphql). `api_version` overrides the default `2026-10`. |
| `check_access` | Reports what the account can read: catalog, orders, customers and inventory. |
| `get_shop` | The store name, myshopify.com host, currency, time zone and primary domain. |
| `list_orders`, `get_order` | Orders, newest first, and one order with its line items. |
| `list_draft_orders`, `create_draft_order`, `delete_draft_order` | Draft orders. `create_draft_order` takes a Shopify `DraftOrderInput`. |
| `list_customers` | Customers, most recently updated first. |
| `list_products`, `get_product`, `create_product`, `update_product`, `delete_product` | Products and their variants. Create and update take Shopify's `ProductCreateInput` and `ProductUpdateInput`. |
| `list_locations`, `adjust_inventory` | Locations, and quantity changes. `adjust_inventory` sends Shopify's required idempotency key; pass `idempotency_key` to make a retry safe. |

Ids accept a number (`1001`) or a Shopify id (`gid://shopify/Order/1001`). List actions take `first` (1–250), `after` (the previous page's `endCursor`), `query` (Shopify search syntax) and `reverse`.

## Access and errors

After each Connect, Kortix checks what the token can read and shows it on the connector page, in the form, and in `kortix connectors accounts shopify`:

| Value | Meaning |
| --- | --- |
| `ok` | The account reads it. |
| `blocked` | The app is not approved for protected customer data. Use an app with Custom distribution for this store and connect again. |
| `missing_scope` | The app version lacks the scope. Add it, release the version, approve it on the store and connect again. |

A call never answers an empty list for data it cannot read:

| Error | When |
| --- | --- |
| `protected_data_blocked` (HTTP 403) | Shopify refused orders or customers: the app has no protected customer data access. |
| `scope_missing` (HTTP 403) | The app lacks the scope the call needs. The error names it. |
| `credential_rejected` … `reconnect_required` (HTTP 424) | Shopify refused the token: the app was uninstalled or its access revoked. Connect the account again. |
| `shopify_throttled` (HTTP 429) | Shopify rate-limited the store. The response says when to retry. |
| `user_errors` | A mutation's input was refused. The `userErrors` list says why. |

When the sign-in fails, the form names the reason: a signature that does not match the app (`invalid_signature`), a store other than the one you entered (`shop_mismatch`), or a refused code exchange (`token_exchange_failed`). Start Connect again.

## A Shopify connector made with Composio

A `composio` connector with `app: shopify` keeps working. Its account connects with the client credentials of an app in the same Shopify organization as the store, and Composio's shared app cannot read orders. Add a `shopify` connector for full access.
