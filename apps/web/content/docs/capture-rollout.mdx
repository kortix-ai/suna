title: Capture IT rollout
description: Install Kortix Capture on many computers with one enrollment token. Each computer enrolls and records on its own, with no sign-in to Kortix, and you link it to a person when you want.
---

IT installs Kortix Capture, the separate recorder app, on every computer with
one command. The installer adds a Windows service. At each Windows sign-in the
service enrolls the computer and starts recording. Nobody signs in to Kortix
by hand, nobody needs a Kortix account, and nobody can quit the recorder
except IT.

This page is for the IT team and the Kortix account admins. For one person on
their own computer, see [Capture → Install Kortix Capture](/docs/capture#install-kortix-capture).

## How it works

1. An account admin creates an **enrollment token** in Kortix.
2. IT installs `KortixCapture-x64.msi` on each computer with the Kortix URL and the
   token. The installer writes both to the registry and starts the
   **Kortix Capture** Windows service.
3. At each Windows sign-in the service reads the person's Windows sign-in
   name (the user principal name, for example `jane@corp.example`) and enrolls
   the computer with the token.
4. The computer gets a device token and starts recording. When an account
   member has that email, the computer is linked to them and records into
   their timeline. Otherwise it records **linked to no one** until an admin
   links it to a person.
5. The person sees an icon in the notification area and, at every sign-in, a
   notice that names the organization.

The service runs as `LocalSystem`. It starts the recorder in each signed-in
session as that person, and starts it again within seconds when it stops.
The enrollment token stays with the service: the registry key that holds it is
readable by SYSTEM and administrators only, and the person's processes never
see it.

## Before you start

- Turn on Capture for the account and set the policy: what is recorded, the
  frame rate, exclusions, retention and **the notice** the person sees. See
  [Capture → The policy](/docs/capture#the-policy).
- People do not need Kortix accounts. When a person is a member with the
  email they sign in to Windows with (SCIM provisioning or an invite), their
  computer is linked to them at once; any other computer records linked to no
  one, and you link it later.
- You need the `capture.manage` permission. Account owners and admins have it.

## 1. Create an enrollment token

In Kortix, open **Capture → Devices**, then **Roll out**. Fill in:

| Field | What it does |
|---|---|
| Name | A name for the rollout, for example the computer group. |
| Email domains | Only people who sign in to Windows with these domains enroll. Empty: any member. |
| Computer limit | At most this many computers enroll with the token. Empty: no limit. |
| Expires | 7, 30 or 90 days, or never. Computers enrolled before it expires keep recording. |
| Approve each computer | Every new computer waits for an admin, also when its person is a member. |

Kortix shows the token (`kortix_enr_…`) once. Copy it with the install
command next to it. Anyone who has the token can enroll computers into the
account until you revoke it, so handle it like a password.

From the API: `POST /v1/accounts/<account_id>/capture/enrollment-tokens` with
`{"name": "Pilot laptops", "email_domains": ["corp.example"], "max_devices": 20}`.

## 2. Install on each computer

Run as an administrator:

```powershell
msiexec /i KortixCapture-x64.msi /qn KORTIX_URL=https://api.kortix.com ENROLLMENT_TOKEN=kortix_enr_...
```

`KORTIX_URL` is the address of your Kortix API without `/v1`. Self-hosted
Kortix uses its own API address. The installer marks `ENROLLMENT_TOKEN` as
hidden, so it does not appear in installer logs.

With Microsoft Intune, add the MSI as a line-of-business or Win32 app and use
the command line above. With Group Policy or another tool, install the MSI
without properties and write the two registry values yourself:

| Key | Value | Type |
|---|---|---|
| `HKLM\SOFTWARE\Policies\Kortix\Capture` | `Url` | `REG_SZ` |
| `HKLM\SOFTWARE\Policies\Kortix\Capture` | `EnrollmentToken` | `REG_SZ` |

An upgrade (`msiexec /i` with a newer MSI) keeps the registry values when you
pass no properties.

## 3. Check the rollout

**Capture → Devices** lists every enrolled computer with an **IT rollout**
badge, under its person or under **Linked to no one**, with its live state:
recording, paused, offline. A computer reports within a minute of the first
Windows sign-in.

To link a computer to a person, choose **Link to a person…** on it. What it
recorded linked to no one moves to that person. See
[Capture → Link a computer to a person](/docs/capture#link-a-computer-to-a-person).

**Waiting for approval** lists computers that wait for an admin: the token
approves each computer, or an admin revoked this one. For each, choose
**Approve** (and, if you like, the person it records for) or **Deny**. An
approved computer starts recording within a minute.

On the computer:

```powershell
sc query KortixCapture
Get-Process kortix-capture | Select-Object Id, SessionId
```

The service is `RUNNING`, and a `kortix-capture` process runs in each
signed-in session.

## Remove a computer or stop a rollout

| To | Do |
|---|---|
| Stop new computers from enrolling | Revoke the token in **Roll out**. Enrolled computers keep recording. |
| Stop one computer | Revoke the device in **Devices**, or deny it in **Waiting for approval**. Its device token stops working at once. The computer does not enroll again until an admin approves it. |
| Remove Kortix Capture | `msiexec /x KortixCapture-x64.msi /qn`. The service and the program files go away. Recordings on the computer stay in each person's profile until retention deletes them. |

## What the enrollment token can and cannot do

- It enrolls computers into one account, within its domains, limit and
  expiry. It cannot read anything.
- A device token, which each enrolled computer gets, uploads that computer's
  recordings and reads the account's policy. It cannot read recordings.
- Kortix trusts the Windows sign-in name the way a badge reader trusts a
  badge. An administrator of a computer can change what that computer
  reports. If that matters to you, turn on **Approve each computer** and check
  each computer before you approve it.
- Every enrollment, token change and decision is in the account's audit log:
  `capture.device.enroll`, `capture.enrollment_token.create`,
  `capture.enrollment_token.revoke`, `capture.enrollment.approve`,
  `capture.enrollment.deny`, `capture.device.link`.

## Answers from enroll

The service shows these in its log (`%ProgramData%\Kortix\Capture\logs`) and
retries on its own.

| Answer | Means | The computer |
|---|---|---|
| `enrolled` | The token is valid. `member` names the linked person, or is `null` while the computer is linked to no one. | records |
| `pending` `approval_required` | The token approves each computer, or an admin revoked this one. | waits; asks again every minute |
| `401` `enrollment_token_invalid` | The token is unknown, revoked or expired. | asks again every hour |
| `403` `enrollment_domain_not_allowed` | The sign-in domain is not one of the token's. | asks again every 6 hours |
| `403` `enrollment_limit_reached` | The token reached its computer limit. | asks again every hour |
| `403` `enrollment_denied` | An admin denied this computer. | asks again every 6 hours |
| `403` `capture_disabled` | Capture is off for the account. | asks again every hour |

## macOS and Linux

The silent install with an enrollment token is Windows only for now. On macOS
and Linux each person installs Kortix Capture and chooses
**Sign in with Kortix…** ([Capture → Install Kortix Capture](/docs/capture#install-kortix-capture)).
