`kortix mcp` serves the [Kortix CLI](/docs/cli) over the Model Context Protocol (MCP), on stdio. Each top-level CLI command is one tool. The MCP surface and the CLI are the same surface: a command added to the CLI is a tool here, with no second step.

In the web app, open the workspace menu and select **Connect MCP**. The dialog shows the commands below, already filled in for your deployment.

## Set up

<Steps>

<Step title="Install the CLI">
```sh
curl -fsSL https://kortix.com/install | bash
```
</Step>

<Step title="Sign in">
```sh
kortix login
```

The MCP server acts as this login, on the active host. To act as a different identity, set `KORTIX_TOKEN` (and `KORTIX_API_URL` for a host other than Kortix Cloud) in the server's environment. See [Auth model](/docs/cli#auth-model).
</Step>

<Step title="Add it to your client">
Claude Code:

```sh
claude mcp add --scope user kortix -- kortix mcp
```

Codex:

```sh
codex mcp add kortix -- kortix mcp
```

Cursor, Claude Desktop, VS Code, Windsurf, and other clients take this JSON in their MCP settings:

```json
{
  "mcpServers": {
    "kortix": { "command": "kortix", "args": ["mcp"] }
  }
}
```
</Step>

</Steps>

## How a tool call works

A tool takes the arguments that follow `kortix <command>`:

```json
{ "name": "sessions", "arguments": { "args": ["ls", "--json"] } }
```

This call runs `kortix sessions ls --json` as a child process and returns what it printed.

| Input | Type | Effect |
| --- | --- | --- |
| `args` | `string[]` | The arguments after `kortix <command>`, one element per argument. Default `[]`. |
| `stdin` | `string` | Text piped to the command, for arguments given as `-`. |
| `timeout_seconds` | `number` | Kill the command after this many seconds. Default `300`, maximum `3600`. |

The result has up to three text blocks:

1. The command's stdout. With `--json` it is valid JSON by itself.
2. `[stderr]` and the command's stderr, when it wrote any. The CLI writes the active host line and errors here.
3. `[exit code N]` or `[killed after Ns; raise timeout_seconds]`, when the command failed. The result is then marked `isError`.

The child process has no terminal. The CLI's non-interactive rules apply: no color, no prompts, and no update question. A command that asks a question without a terminal takes its documented default or fails. Pass the flag that answers the question instead, for example `--yes` or `--account <slug>`.

Calls run in parallel. A client cancellation (`notifications/cancelled`) stops that call's process. When the client disconnects, the server stops every process that is still running.

## Tools

The tools are the commands in `kortix --help`, except six that take over a terminal or replace the binary: `mcp`, `connect`, `tui`, `update`, `uninstall`, and `help`.

Start with `system-skills`. It lists the platform guides that the host serves, and `["get", "<name>"]` reads one. Pass `["--help"]` to any tool to read its subcommands and flags.

## Connectors inside a session

A session sandbox has a separate server, `kortix connectors mcp`. It exposes only the project's [connectors](/docs/connect/connectors), as a small set of discovery and call tools. `kortix mcp` is the whole CLI, for a client outside Kortix.
