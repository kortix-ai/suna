A **template** is a Kortix project you install into your own: a public GitHub
repository whose `kortix.yaml` declares agents, skills, connectors and
triggers. Installing one merges that declaration into the target project.

Templates is a [feature flag](/docs/feature-flags). Its stability is
**experimental**, and it is off by default. Turn it on per project before you
install anything.

Building on the template catalog from TypeScript? See
[SDK → Templates](/docs/sdk/templates) for the client surface and the React
hooks.

## Turn Templates on

Open **Settings → Feature flags** and switch **Templates** on for the
project. You need `project.customize.write`.

While the flag is off:

- `POST /v1/projects/:id/templates/install-session` answers `403` with
  `{ error, code: "feature_disabled", feature: "templates" }`.
- `kortix templates install` prints the same sentence and exits `1`.
- The **Templates** tab does not appear in the Customize tab bar.

The public catalog is not gated. `/templates` and
`GET /v1/public/templates` answer for everyone, signed in or not.

## The catalog

The catalog is a curated, static list that ships with the API
(`apps/api/src/templates/catalog.ts`). Each template names a public GitHub
repository and the exact commit its card was derived from. There is no
submit, upload or publish step: adding a template is a change to that list.

| Surface      | Where                                                              |
| ------------ | ------------------------------------------------------------------ |
| Public page  | `/templates` and `/templates/<slug>`                               |
| In a project | **Customize → Templates**                                          |
| API          | `GET /v1/public/templates?q=` and `GET /v1/public/templates/:slug` |
| CLI          | `kortix templates list` and `kortix templates show <slug>`         |

Every card shows what the template brings — agents, skills, triggers with
their cadence, the connectors it needs and the secrets you provide — and links
to its source repository.

## Install

Installing is agent-driven. `Install` starts a session whose agent:

1. reads the template's files at the pinned commit and this project's current
   `kortix.yaml`;
2. installs at the project root — a template is an example project setup, not
   a subproject. The agent may ask once whether you want it as a subproject and
   does nothing of the kind unless you say so;
3. copies the template's agents and skills, renaming on a name collision and
   never touching `default_agent`;
4. merges its connectors, keeping an existing connector that may already hold
   credentials;
5. merges its triggers with every one **disabled**;
6. walks you through the connectors and secrets it needs, with setup links —
   never a pasted key;
7. runs `kortix validate` and opens **one** change request.

Nothing lands until you merge that change request. After the merge, enable the
triggers one at a time from **Customize → Triggers**.

:::info[Uninstall is a revert]
Nothing records what a project has installed. Everything a template adds lands
in the one change request the install opened, so reverting that commit removes
it. There is no installed list, no uninstall button and no per-template switch.
:::

## Permissions

| Action                  | Permission                |
| ----------------------- | ------------------------- |
| Browse the catalog      | none — public             |
| Install into a project  | `project.write`           |
| Turn the flag on or off | `project.customize.write` |
