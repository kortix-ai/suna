# Register every model a sandbox is told to use; the gateway decides whether it is served, never the box's catalog

**Rule:** The sandbox never decides whether a model exists. OpenCode answers `Model not found` for an id its `kortix` provider map lacks, and that map is a snapshot of the image-baked catalog. So the composed config registers every model the box is told to use: the ones the config names (`model`, `small_model`, agent models, agent `.md` models, the session model) and the one a turn names (`POST /kortix/catalog/converge {model}`). The gateway answers for a model it does not serve. A list the box fetches supplies limits and capabilities only. Apply a provider-map change with `reloadConfig` (`/global/dispose`, same process), behind the idle check: a dispose aborts a running turn.

**Trigger surface:** Composing OpenCode's provider map (`buildKortixProvider`, `convergeManagedModelCatalog`, `applyCatalogIfIdle` in `apps/kortix-sandbox-agent-server/src/harness/open-code/lifecycle.ts`), adding a path that sends a prompt without a model, adding a model source (a provider lineup, a default, a Routing chain), or adding a new OpenCode restart for a config change.

**Incident:** 2026-10-02, prod. A session turn failed with `Model not found: kortix/codex/gpt-6.1-sol`, with `codex/gpt-6-sol` offered as the nearest id. The box ran an image catalog older than the model. It is the fourth incident of this class (after 2026-08-19, 2026-09-26 and 2026-10-01). Each earlier fix added one more fetch of one more list: the repair still depended on a 5 MB catalog fetch inside a 4 s budget and on a verified OpenCode restart inside the API's 8 s wait, and it ran only when the prompt body named the model. A prompt with no model (email, question answers, change-request feedback, model-less triggers, subagents) ran on the config's model and passed no gate. The prod logs of the failing turn were not read, so which of those gaps it hit is not known. Measured on a local stack with real Platinum boxes: the repair took 3,392 ms before (OpenCode pid changed) and 460 ms after (same pid).

**Enforcement:** `apps/kortix-sandbox-agent-server/src/__tests__/opencode-lifecycle.e2e.test.ts` › "a model a turn names" (a real lifecycle, a fake `opencode` binary and a gateway on a real port: the model is in the config OpenCode re-reads, on the same pid, when the listing carries it and when the listing fetch fails) and › "agent .md model refs" ("an .md model no catalog carries is registered on the kortix provider"). `opencode-catalog.test.ts` › "every model the config names is registered, even when no catalog carries it" and › "on-demand converge for the ONE model a turn asks for". `apps/api/src/sandbox-proxy/command-env-sync.test.ts` pins the Kortix prompt route body the turn-start gate reads the model from. Not enforced: a turn on a real sandbox whose image predates the model. Run it by hand (PR body) until a funded flow covers it.
