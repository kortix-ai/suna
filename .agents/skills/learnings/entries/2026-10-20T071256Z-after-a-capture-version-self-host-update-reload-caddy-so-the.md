# After a Capture-version self-host update, reload Caddy so the regenerated kortix-capture route is served

**Rule:** On a domain-mode self-host box, a version-only `kortix self-host update`
regenerates the `Caddyfile` (adding the `@capture` route that proxies
`https://api.<domain>/kortix-capture/*` to `capture-store:9000`) but does NOT
reload the running Caddy. The old config stays live, so Capture device uploads
get the API's JSON `404` on that prefix. After any Capture-version self-host
update, reload Caddy and prove the prefix reaches the store:
`docker exec <project>-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile`,
then `curl -s https://api.<domain>/kortix-capture/` must return a MinIO S3 XML
error (e.g. `403 AccessDenied`, bucket `kortix-capture`), never the API's
`{"error":true,"status":404}`. The reload is graceful (zero downtime); API
health stays `200`.

**Trigger surface:** Upgrading a self-hosted deployment to a new Kortix version
and expecting Kortix Capture devices to sync. Symptom: an enrolled device records
locally and fetches S3 credentials, but `sync status` shows
`last_error_class: config`, `PUT .../kortix-capture/... HTTP 404`, and
`uploaded: 0` while `pending` grows. `kortix self-host doctor` still reports
`✓ capture-store` (the container and the on-disk Caddyfile are fine — only the
in-memory Caddy config is stale), which hides the real cause.

**Incident:** 2026-10-20, v0.14.3 self-host update on a domain-mode box. The box
had a healthy `capture-store` (MinIO) and a correct on-disk `Caddyfile` with the
`@capture` route (regenerated by the update), plus full `KORTIX_CAPTURE_S3_*`
env on `kortix-api`. But the Caddy container had been up ~8 weeks and never
reloaded, so every device upload hit the API and `404`ed. A test PC enrolled,
signed (CN=Kortix AI Corp) and recorded locally, but zero frames reached the
box. `caddy reload` fixed it with no downtime; both test PCs then synced
(`uploaded>0`) and frames appeared in the account timeline. Blast radius: Capture
sync silently broken on any self-host box upgraded without a Caddy reload.

**Enforcement:** none yet. Build: `kortix self-host update` in domain mode should
reload Caddy after it regenerates the `Caddyfile` (and `kortix self-host doctor`
should probe `https://api.<domain>/kortix-capture/` for a MinIO response, not
just assert the container exists, so a stale router turns the check red).
